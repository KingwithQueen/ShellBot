## 文件范围与目录外可见性

每个项目包含多个 workspace，分别指定稳定标识、实际目录和读写权限。默认目录外不可见；所有者可以增授额外目录只读、读写，或当前账户有权访问的全部文件。范围以可信本机配置和实际文件句柄检查为准，不接受客户端 roots、cwd 或模型参数作为授权来源。

列表、搜索摘要、图像和文档阅读均属于文件访问，不允许它们绕过目录限制或读取审批。拒绝访问时只返回必要的错误，不泄露未授权目录条目和文件内容。全部文件访问仍受实际普通或提升令牌限制，不保证访问 SYSTEM/TrustedInstaller 保护对象。

项目 MCP 链接及凭据固定项目上下文；AI 可以选择本项目已配置的 workspace_id，不能通过 project_id 切换到另一项目。额外目录授予属于所有者管理操作，批准一次文件操作不会永久扩大项目范围。

## 三种操作审批模式

| 模式 | 文件操作 | 命令及交互输入 |
| --- | --- | --- |
| always | 每次逻辑访问审批，包括列表、读取、搜索、图像/文档阅读、写入和修改 | 启动及输入逐次审批 |
| workspace_auto | 本项目允许的工作目录内读写自动；只读目录仍不可写；获准访问的额外目录默认审批 | 启动及输入逐次审批 |
| never | 在已授予范围和已启用工具内自动执行 | 在已授予身份和能力内自动执行 |

模式不改变文件范围、只读属性、工具开关或管理员许可。所有模式在执行前重新验证项目、策略和对象状态。审批绑定一次完整、有预算的逻辑操作；同目标、同版本和同范围的分页可延续许可，目标变化或扩大范围后重新检查。

主机状态与能力查询只显示当前项目允许的元数据。任务状态、输出归属原已批准任务，不为轮询重复审批；task_input 单独绑定输入内容和 EOF。task_cancel 无需新增批准，但只能取消本项目本人任务；项目停用与所有者暂停也始终可用。

文件修改继续使用预期原始哈希、对象身份、结果摘要和备份等已有保护；never 只是免除逐次询问，不免除修改冲突和实际路径检查。未授予的操作直接拒绝，申请长期扩权须走所有者配置入口。

## 执行身份与隔离边界

| 身份 | 系统能力 | 与审批的关系 |
| --- | --- | --- |
| restricted | M4 实际 LPAC、逐实例目录 ACL、零 capabilities、禁止 Win32k/子进程；启动行为验证 | 可搭配三种审批模式；批准不解除系统限制 |
| current_user | 启动者真实普通令牌；属于管理员组也不自动提升 | 可搭配三种模式，但任意命令仍有该账户的系统访问能力 |
| administrator | 已经提升的代理执行明确操作，不将普通项目工作进程整体提升 | 必须由所有者单独允许该项目使用；仍遵守项目审批、工具和文件范围 |

普通任务默认 restricted 或 current_user；管理员操作必须明确选择身份并通过授权代理。程序清单继续 asInvoker，普通入口、网关和管理器不统一提升；user 后端现有拒绝已提升主机的行为保留到身份拆分完成。

只有工作目录或命令 cwd 不能隔离任意程序。严格目录受限项目必须验证任务无法访问未授权文件、读取凭据、修改配置、调用审批/管理员接口，以及无法通过子进程、链接、脚本和继承句柄逃逸。新建低权限账户或准备低完整性令牌都只是实现步骤，不是完整沙箱的验收结论；未通过的后端报告不可用。

受限执行所需的程序和系统库按明确的只读运行资源许可处理，不因此向 AI 开放其他用户文件。网络、桌面及管理对象保护独立设计和验收，不能由文件目录检查替代。

M4 每实例创建独立 AppContainer profile，明确退出 ALL APPLICATION PACKAGES 授权，再用实际 AccessCheck 对照证明不能借该通用包组访问文件。除声明的只读 runtime_files 外，只授予配置的目录；读写目录不授予 WRITE_DAC/WRITE_OWNER。启动检查与原生专项核验实际令牌、目录读写、管理 Data、注册表、父进程注入、网络、Win32k 与子进程。Windows 定义见 [Microsoft AppContainer/LPAC](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)。

此后端初期只支持兼容这些限制的原生程序，不开放通用子进程树、GUI、网络或 registry 能力；缺资源或核验失败保持关闭。LPAC 的平台运行资源和自身 profile 不等于仅可见 cwd 的虚拟机；它也不隔离所有者授权的 current_user/administrator 程序。M4 的本机证据不能替代 Windows 10/Server 或任意第三方工具兼容性验收。

初期严格受限项目禁止管理员执行。若所有者选择 current_user 任意命令或管理员能力，则该项目属于账户级信任模式，界面和能力报告不能继续宣称任意命令被严格限制在目录内。管理员项目可能修改整台电脑，多个工作进程和 API 授权不能提供抵抗管理员程序的互相隔离；这种需求另用虚拟机或独立系统。

## 可预配置的项目示例

| 项目 | 文件范围与审批 | 普通执行 | 管理员使用 |
| --- | --- | --- | --- |
| A 完整权限 | 当前账户可访问范围，never | current_user，任意已启用命令 | 所有者允许后可用；启动代理仍需 UAC |
| B 工作目录自动 | 多个工作目录，workspace_auto，目录外拒绝 | restricted，命令和输入审批 | 默认禁止 |
| C 每次确认 | 配置的目录，always | restricted，命令和输入审批 | 默认禁止 |

可同时保存上述项目。完整权限项目不等于永远以管理员身份执行；管理员保护文件和命令只有在实际提升后端可用、项目已允许且本次操作满足策略时才执行。文件工具需要提升时也经过同一代理授权检查，不能靠任意管理员命令绕过项目文件策略。

## 共享管理员代理与 UAC

同一管理器管理一个常驻管理员代理，按需共享给已经允许管理员执行的项目。代理只接受受保护本机通信，独立验证调用进程、注册项目、授权版本、操作摘要、期限及必要的批准记录；可信注册和撤销由所有者管理端完成。只凭同账户 SID、请求内 project_id 或 approved=true 不能取得权限，模型没有注册项目、自批或修改权限的工具。

所有者可以启动前允许 A/B、禁止 C，然后启动代理完成一次 UAC。A/B 复用代理，C 仍被拒绝。提升的是代理进程，普通工作进程不继承提升令牌。Windows 的进程令牌和 UAC 行为见 [Microsoft UAC 工作方式](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works)。

代理已提升后新增项目许可，需要新的 ShellBot 所有者授权，通常不会自然产生另一遍 Windows UAC。如果要求每项目首次使用都实际弹 UAC，可使用独立管理员代理；默认共享方案不承诺这种行为。UAC 被拒绝、身份不匹配或代理死亡时标记管理员能力不可用，不静默降级执行、不自动再次提权。

单项目退出不关闭仍被其他项目使用的代理。撤销管理员许可后拒绝该项目新操作并取消未启动操作；停用项目终止本人受管任务。策略收窄使旧审批失效，活动任务默认取消并记录真实结果；已经发生的副作用和已执行管理员代码不承诺回滚或完全降权。

一次 UAC 覆盖当前代理运行期；电脑重启或代理退出后的再次启动需要重新授权。以后可通过首次安装授权的服务/计划任务支持自动恢复，当前不安装这类组件。跨账户 UAC 身份须分别记录并单独验收，不把启动者和管理员账户当作同一个用户。

## 所有者审批与无人值守

本机管理和后续远程审批使用独立所有者身份或凭据；MCP 凭据只允许提出、查询和取消本人请求。审批链接不能是持有即可批准的令牌，打开链接、客户端确认打开网页或 AI 声称用户同意都不产生批准记录。

审批绑定认证主体、host/worker 实例、项目、工作目录、操作、规范化目标及对象身份、文件/脚本内容和程序参数摘要、输入与 EOF、执行身份、策略版本和有效期；变化后重新检查。解释器规则不能只按可执行文件名放行任意脚本，需绑定实际内容及资源范围。

客户端声明并经验证支持交互时可提供 MCP elicitation 提示，否则返回待审批编号和管理入口说明；协议提示不替代真实所有者批准。等待审批释放工作线程，拒绝、过期、断线或超时不自动批准；重试复用原请求/任务，避免重复副作用。

远程审批提供请求查看、接受和拒绝等有限操作，不开放一般配置与命令入口。其身份验证是独立开发项，不恢复已暂缓的 MCP OAuth、域名检查或 cloudflared 管理。当前 owner 命名管道仍只能本机管理，不能描述为已支持远程审批。

## 新旧配置过渡

新配置版本将项目、审批模式、执行身份与管理员许可分开。旧单实例配置只能显式迁移；保留旧文件目录和审批限制，不把 user/administrator 自动转换为全盘文件访问或免除文件审批。迁移前备份原配置，不改旧 Data。未来的模式名称和权限字段不能直接放入 dev.7 配置使用；后文列出当前实际解析规则。

## dev.7 配置与试用

配置示例默认不启用执行后端：

```json
"execution": { "enabled": false, "profile": "controlled", "approval_mode": "always" }
```

profile 接受 controlled、user、administrator；approval_mode 仅用于 controlled，接受 always 或 rules。user 与 administrator 使用预先授权方式，不能同时填写 approval_mode。未知、重复或错误类型的字段拒绝，不接受模型自报的 elevated、approved 或 root 等扩权设置；规则列表尚未支持，填写 rules 字段会报错。

使用 --execution-status 可读取配置及真实令牌信息；host_info 与 host_capabilities 也返回 execution_status。身份信息包括账户 SID、实际进程、会话、完整性级别、提升状态、管理员组是否启用、限制 SID 和 AppContainer 标志。SID 用于区分身份，不代表该身份已授予命令权限。

enabled:true 初始化身份后端，并在 user/administrator 后端就绪时提供命令任务。controlled 准备低完整性受限令牌，但仍报告 controlled_isolation_verified:false；只验证该令牌被管理入口拒绝，不把准备令牌称为完整目录、网络或桌面沙箱。user 拒绝已提升的主机，避免把真实管理员身份报告为普通用户。administrator 请求启动常驻代理，在身份检查通过后接受任务操作；主入口保持普通权限。

管理员代理通道限制访问者并拒绝远程管道连接，双方检查实际对端进程；主机检查返回进程句柄、实际管道对端令牌与身份回复，代理检查父进程与同一可执行文件路径。代理使用 SECURITY_IDENTIFICATION 连接，普通权限主机不能借此获得管理员模拟身份。重复身份查询复用同一代理；主机正常退出关闭代理，管道断开时代理退出。同账户真实提权、重复查询和正常退出已通过 Server 2025 独立验证；跨账户路径仍需单独验证。

当前共十三个工具，五个任务工具要求当前 host_instance_id；未启用执行或 controlled 隔离尚未完成时拒绝任务。八个既有工具保持原有文件策略；远程审批仍不可用。启用 administrator 的诊断会触发启动授权，因此常规脚本不自动测试此路径。--execution-status 是本机诊断命令；MCP 只能查看状态，不能通过工具参数改档位或启动新代理。

专项脚本 Test-ShellBot-Permissions.ps1 默认测试三档配置、普通身份、受限调用者拒绝和能力报告；加 -Administrator 才请求一次启动授权并连续查询同一代理、检查退出清理。必须在普通权限 PowerShell 运行才能同时覆盖前两档和首次 UAC。脚本不自动观察弹窗次数，也不测试命令执行；已有提升环境下会明确跳过普通用户与受限调用者场景。

按规则执行需要固定允许的程序、参数条件、工作目录和能力范围。任意 PowerShell/cmd 脚本、解释器和可修改脚本不能仅按可执行文件名前缀认定为安全规则。申请在 user 或 administrator 档执行的请求不能借 controlled 档规则自行升档。

## 新设计验收条件

1. 项目 A/B 可预先允许管理员能力，C 禁止；一次代理启动 UAC 后 A/B 复用，C 仍被拒绝。
2. 项目凭据、worker 实例、workspace、任务、审批和幂等回执不得串项目；伪造 project_id 或同账户 SID 不构成授权。
3. always 下读取和修改未批准不执行；workspace_auto 下目录内自动读写但命令等待；never 不增加文件范围或管理员许可。
4. 受限命令批准后仍不能访问未授权目录、管理凭据和审批/代理接口；受限后端未通过时拒绝执行。
5. 新增管理员项目需要所有者批准；共享代理已经提升时不承诺再弹实际 UAC。撤销和策略收窄后拒绝旧审批与未启动请求。
6. 所有者可从另一设备完成独立审批；MCP 令牌不能自批。参数变化、过期、拒绝、断线均不会自动执行。
7. 普通入口和普通任务保持真实普通令牌；管理员操作实际提升。拒绝 UAC、代理死亡、跨账户启动、项目退出与取消分别记录真实结果。

Windows 10/11、Server 2025 和目标 MCP 客户端分别验收；设计文档、受限令牌准备和本机自检不能代替完整隔离及实际客户端证据。

## dev.7 本机任务证据

Windows 11 专业工作站版 build 26300 上，原生辅助程序专项普通权限通过 89 项、管理员权限通过 94 项。主入口未提升，管理员任务实际提升，多任务复用同一代理，输入、超时、取消、退出清理均通过。用户在首次原生专项后另行确认“没有新的杀毒告警，UAC 仅出现一次”；脚本字段仍为 not_observed_automatically，不改成自动统计。

该轮任务专项直接运行 C 测试辅助程序，已移除编码 PowerShell 子命令；没有调整杀毒、UAC 或系统执行策略。跨账户管理员、Server 2025 dev.7 命令任务和受控隔离仍需各自验收。工具调用与回执限制见 [COMMAND_TASKS.md](COMMAND_TASKS.md)。
