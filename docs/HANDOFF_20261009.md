## 用户意图与已确认范围

ShellBot 是让无法安装 ChatGPT 客户端的电脑也能提供 MCP 工具的原生电脑控制主机。GPT/其他模型服务负责推理；本程序提供文件、图像、命令任务及后续桌面和文档能力，不内置模型或持续聊天代理循环。发行程序不依赖 Node.js、Python 或开发环境；开发验证可以使用 Python。

主平台为 Windows 10/11，用户已准备 Windows Server 2025 测试电脑，也同意先在本机 Windows 11 测试。Linux/macOS 通过独立 C 核心和平台接口预留；Windows 7/8.1 以后单独编译与验收，不为旧系统降低当前 WinShellBot 的优化。

外部隧道由用户已有环境完成。默认监听 **127.0.0.1:8765，原生 HTTP**，不在程序内配置本机 TLS；已有 bearer 认证继续保留。用户曾提供域名 shellbot.jsnowly.win，并说明 cloudflared 在其他程序已测试通过；本次没有重新检查域名或隧道。外部地址填写与 public_url 限制可选，不要求域名才能启动。

**当前不开发公网 OAuth、cloudflared 安装/监管、DNS 检查或域名探测，不修改用户现有隧道。** 独立所有者远程操作审批属于另一个待开发能力，不意味着恢复上述开发范围。

## 新架构和权限决定

采用 **普通权限管理器 + 每项目独立工作进程 + 按项目授权的共享管理员代理**。可复用 WinShellBot.exe 的不同启动角色，不必立即增加多个二进制或运行时。架构属于待开发目标，当前 dev.7 仍是单实例配置和单主机代理。

每项目独立配置、凭据引用、任务/幂等记录、审批队列、备份、审计和资源预算；每项目多个 workspace，分别配置读写权限和默认 cwd。网关默认共用回环端口 8765，提供 `/projects/{project_id}/mcp` 地址；路由和认证确定项目，A 的凭据不能访问 B，模型自报 project_id 不能切换项目。旧 `/mcp` 仅显式绑定默认项目；独立 stdio 和多实例仍可作为部署方式。

权限判断顺序：认证及项目绑定 → 工具开关 → 文件范围/执行身份上限 → 审批策略 → 执行前重新核验。以下设置互相独立：

| 设置 | 已确认行为 |
| --- | --- |
| 文件范围 | 默认仅配置的工作目录；可额外授予指定目录只读/读写，或当前账户可访问的全部文件 |
| always | 每次文件逻辑访问及命令启动/输入需要批准，包括列表、读取、搜索、图像及后续文档阅读 |
| workspace_auto | 允许的工作目录内读写自动，命令启动/输入需要批准；额外目录操作默认审批 |
| never | 授权范围内自动操作，不增加文件范围、写权限、工具能力或管理员许可 |
| 执行身份 | 受限或当前账户普通任务；管理员操作明确选择并交由已经提升的授权代理 |
| 管理员许可 | 所有者单独允许哪些项目可以使用代理；默认关闭，MCP 无法自行启用 |

用户明确要求同时配置这两类项目：

- 完整权限项目：当前账户可访问的文件范围，never，默认普通账户执行；可以单独允许管理员操作。
- 工作目录项目：一个或多个工作目录，目录外拒绝，workspace_auto；命令审批并采用经过验证的受限执行后端，管理员默认禁止。

审批只能允许原范围内操作；扩大目录或启用管理员能力属于所有者配置变更。只读目录不因 never 或批准而变成可写。批准一次有预算且绑定目标、版本和范围的逻辑读取，分页可延续许可，不为每页反复确认；文件改变或增加范围重新判断。

task_status/task_output 校验项目和任务归属，属于原授权任务结果，不为轮询重复审批。task_input 单独绑定文本和 EOF。task_cancel 无需新增批准，但只能取消本项目本人任务；所有者暂停或停用项目始终可用。

### 管理员代理的明确边界

所有者可以启动前允许 A/B、禁止 C，再完成一次代理启动 UAC。A/B 的管理员操作复用代理，C 始终拒绝；普通网关和工作进程不提升。代理独立核验实际对端、可信项目注册、授权版本和本次操作，不能仅信任同账户 SID、project_id 或 approved=true。

**UAC 提升进程，不识别 ShellBot 项目。**代理已经提升后再新增允许项目，需要一次独立的 ShellBot 所有者授权，但通常不会自然再次弹 Windows UAC。若用户以后要求每项目首次使用都必须真正弹 UAC，采用每项目独立代理；这是可选方式，不是默认方案。

单项目退出不终止其他项目共用的代理或任务。撤销后拒绝新请求并取消尚未开始的操作；策略收窄使旧审批失效，活动任务默认取消并记录实际结果。代理死亡或 UAC 拒绝时报告管理员不可用，不隐式重提权或按另一身份执行。一次 UAC 只覆盖当前代理运行期；电脑重启后的自动管理员恢复以后通过服务/计划任务设计。

### 隔离与无人值守

cwd、文件工具的目录列表、Job Object 或准备受限令牌都不等于任意命令沙箱。严格目录受限任务需要验证身份、对象 ACL、运行资源白名单及管理资源保护；必要系统库只读许可不能开放其他用户文件。完整隔离未验收前，受限命令保持不可用。

当前账户任意命令和管理员命令属于账户级信任模式，可以影响对应账户或整台电脑，不能承诺无法干扰其他项目。严格受限项目初期禁止管理员执行；抵抗管理员能力的隔离应另用虚拟机或独立系统。

远程审批将由另一设备的所有者独立入口处理，身份与 MCP 凭据分开。AI 只能申请、查询和取消，不能自批、改配置或永久扩权。打开链接或 MCP 客户端同意打开网页不等于批准。MCP elicitation 只按客户端实际声明、验证的能力接入；不支持时返回请求编号和管理入口说明。当前没有远程审批。

## 当前 dev.7 已实现内容

十三个工具：host_info、host_capabilities、fs_list、fs_read、fs_search、image_view、fs_write、fs_patch、task_start、task_status、task_output、task_input、task_cancel。

- stdio 与回环 HTTP，支持三个 2025 年初始化协议子集和 2026-07-28 每请求元数据；HTTP 校验对应请求头。无 SSE、标准 MCP tasks 扩展和 elicitation。
- 单实例最多 16 个显式工作目录，默认只读；文件工具核验真实句柄路径，拒绝逃逸路径。文本 UTF-8/UTF-16，搜索支持文件名和有界内容。
- PNG/JPEG 原生 MCP image 返回，只做格式头和预算检查；完整解码、缩放及模型实际获得图像尚待验证。
- 文件创建、绑定原始哈希的覆盖及局部修改、本机所有者审批、私有备份和持久 JSONL 审计。覆盖/修改采用锁定原文件，atomic_save:false，不承诺崩溃原子性。
- 普通用户与管理员后台任务：真实进程身份、stdin/stdout/stderr、超时、取消、输出上限、Job 进程树清理、同实例幂等。管理员常驻代理启动 UAC 一次后复用。
- 有限子进程环境不继承 bearer 和未知变量；程序路径必须绝对本地 .exe，argv 独立数组，不隐式添加 shell 或 PATH 查找。

当前身份配置仍是旧结构，**新权限字段不能直接放进 dev.7 配置使用**：

```json
"execution": { "enabled": false, "profile": "controlled", "approval_mode": "always" }
```

profile 为 controlled/user/administrator；approval_mode 仅允许 controlled 使用 always/rules，user/administrator 填写会拒绝。controlled 虽准备令牌并验证受限调用者不能管理主机，但完整隔离未实现，仍拒绝命令。当前文件读取自动允许，写入需本机批准；user/administrator 命令为预授权自动执行，不是新三审批模式。

### 当前任务契约与限制

所有 task_* 要求当前 host_instance_id。同实例 request_key 绑定调用身份、程序、argv、真实 cwd、workspace 和期限；重试不重复启动，变更参数拒绝。当前摘要不固定可执行文件或脚本内容，不能当作未来受限规则的安全依据。input_key 绑定输入文本及 EOF；queued/delivered 不证明程序已消费。

每实例最多 32 条任务回执、8 个活动任务，每任务最多 64 个所属进程；stdout/stderr 各 256 KiB，单次输出页最多 16 KiB，stdin 每次最多 4 KiB、64 条回执。管理员 IPC 请求 64 KiB、返回 256 KiB，后者已经修复合法控制字符六倍 JSON 转义超预算的问题，不要改回同一小预算。

任务/输出/输入回执在内存，重启不恢复、旧实例请求拒绝，不自动重跑。任务审计仅有操作意图和新启动结果，尚无完整自然终态/输出消费链。日志故障阻止 start 和 input；已知任务的查询、输出、取消仍可用。详见 [任务说明](COMMAND_TASKS.md)、[修改说明](FILE_EDIT.md)和 [审计说明](AUDIT.md)。

## 常用构建与验证入口

在 E:\Program\ShellBot 下运行，先根据改动范围选择必要检查，不为文档或无关小改动重复提权：

```powershell
Set-Location -LiteralPath 'E:\Program\ShellBot'
.\scripts\build.ps1 -Configuration Debug
.\scripts\build.ps1 -Configuration Release
.\scripts\test.ps1 -Configuration Debug -Python 'E:\Program Files\Python\python.exe' -SkipCloseProbe
.\scripts\test.ps1 -Configuration Release -Python 'E:\Program Files\Python\python.exe' -SkipCloseProbe
```

SkipCloseProbe 将核心与历史连接诊断分开，不代表完整 HTTP 测试通过。源码改变后证据必须匹配新程序摘要；旧报告不作为新程序通过依据。

需要验证任务后端时使用原生测试辅助程序：

```powershell
.\tests\Test-ShellBot-Tasks.ps1 -Executable .\out\x64\Release\WinShellBot.exe
# 以下仅在改动涉及管理员执行、需要实际交互验收时运行，会请求启动代理 UAC：
.\tests\Test-ShellBot-Tasks.ps1 -Executable .\out\x64\Release\WinShellBot.exe -Administrator
```

build.ps1 会编译 ShellBot-TestFixture.exe；测试包附该辅助程序和 task_native_fixture.c。程序运行不依赖测试辅助程序。测试用新目录，处理完只清理核验过的本人临时文件，不删除基线、原始报告、旧包或用户项目。

用户此前遇到 powershell.exe 的“Powershell Attack”杀毒告警。任务专项已从 EncodedCommand 改为 C 原生载荷，用户确认无新告警。**不要恢复编码 PowerShell 子命令作为测试载荷，不要关闭杀毒、降低 UAC 或更改系统安全策略。** 普通脚本只是构建/测试入口，与让被测程序启动编码 PowerShell 攻击样式载荷不同。

package-test.ps1 要求匹配当前程序的通过报告；做新候选时用独立目录并记录源码状态、摘要、依赖和跳过项，包内不得带用户数据/令牌/日志。不为了交接重生成 dev.7 包。
