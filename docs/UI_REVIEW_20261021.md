# 管理界面检查与修正（M20）

检查基线：M19 / 0.1.0-dev.26，来源 `HANDOFF_20261021_ARCHIVE.md` 和当前未提交源码。修正候选：0.1.0-dev.27。检查范围为本机管理窗口、项目/连接/数据位置弹窗、客户端授权窗口及权限设置窗口。

## 结论与实现方式

保留现有 C17 / Win32 管理器和业务层，在已有原生控件上调整状态与绘制。主界面已经采用 Win32，无须引入新的 UI 框架。现有 M18 的增量更新和阅读位置保护保留；需要修正的是异步返回、异常刷新、模态循环和其他弹窗尚未统一的行为。

## 代码检查发现

| 问题 | 修正后的行为 | 验证范围 |
| --- | --- | --- |
| 查询诊断后可切换列表，旧项目结果直接写入当前详情 | 请求记录项目和选择代数；返回时仍匹配才显示 | 产品窗口连接独立 owner 通道，确定性延迟响应 |
| 刷新失败清除快照、列表和选区 | 保留最后成功内容，显示状态暂未更新，暂停项目操作；恢复后自动更新 | 错误响应、缺项目标识、重复标识故障注入 |
| 确认框进入嵌套消息循环，计时器仍可发起后台请求，影响确认后的操作 | 确认期间停止发起刷新，退出请求等待模态流程结束 | 真实原生确认框与定时消息 |
| 列表通知的暂时取消选择可能先清空详情 | 合并选择通知，按最终选择变化更新详情；结构更新按项目保留列表顶部 | 真实项目切换与刷新回归 |
| 关闭窗口时已投递的异步结果缺少统一释放路径 | UI 保持工作项所有权，等待线程后释放；工作线程不释放已投递指针 | 延迟诊断期间关闭真实产品窗口 |
| OAuth 每次轮询先禁用再启用按钮；快照变化时整表重建并重置顶部 | 后台查询保持可用操作，排队操作绑定所选连接；仅行集合/文本变化才更新列表，保留选中项、列表顶部与详情选区 | 真实 HTTP 申请、原生无障碍按钮/列表事件及阅读位置观察 |
| 保存线程创建失败后表单没有恢复；连接端口/公共地址没有一起禁用 | 启动失败恢复控件；保存期间统一冻结可编辑字段，失败后可重试 | 代码检查、构建、项目/连接/迁移实际流程；未对系统线程创建强制注入失败 |
| 弹窗未响应 DPI 改变；主窗口字体与逐个移动控件的重绘缺少统一处理 | 系统消息字体，批量窗口布局；共享原生弹窗 DPI 布局和字体生命周期；系统背景一致 | 实际控件边界、重复字体/DPI 消息、GDI 数量；物理跨屏切换另验 |
| 剪贴板打开/写入失败时仍可能提示令牌复制成功 | 只在实际复制成功后提示成功，失败显示可重试原因 | 代码检查和构建；未强制占用系统剪贴板 |
| 嵌套表单消息循环可能吞掉 WM_QUIT | 模态循环重新投递退出消息，交还外层退出流程 | 打开项目弹窗时退出，迁移取消与完整退出回归 |
| 嵌入项目的权限窗口仍显示“保存到新文件”，但实际写回项目弹窗 | 隐藏独立配置专用提示，操作按钮从左侧排列 | 实际控件可见性与截图 |
| 自建 Win32 表单未统一处理默认按钮和 Escape 消息 | 明确默认按钮及确认/取消路由；项目表单 Enter 保存、Escape 取消，授权页默认 Enter 关闭，不隐式批准连接 | 原生键盘消息保存独立项目、关闭/取消弹窗；默认按钮遵循 [Win32 对话框消息](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-isdialogmessagew) |

## Win32 界面

- “文件、项目、连接、工具、帮助”系统菜单；F5、Ctrl+N、Ctrl+E、Ctrl+L 快捷键。
- 全局管理与项目操作分组。操作栏随宽度换行。
- 左侧原生项目列表，右侧只读详情和所选项目操作，底部状态提示。
- 系统字体、按钮、列表、编辑框及菜单。列表双缓冲；稳定内容不重写，控件启用状态只在变化时更新。
- 窗口关闭收进托盘；菜单退出与托盘退出使用同一管理器关闭流程。

## 证据边界

本轮结果与准确程序摘要保存到 `build/native-ui-validation`。`native_ui_checks.py` 使用真实产品窗口和合成管理通道，专门复现时序/错误输入；不能当作真实后端验收。`desktop_app_checks.py`、OAuth、普通管理、权限表单和便携迁移回归另用真实本机管理器。

没有触发真实 Z620 客户端、实际 UAC、物理多屏 DPI、其他 Windows 系统或长期运行验收。没有修改项目权限、真实凭据、系统代理/AdGuard 设置、旧候选包、M19 原始收据。新界面是今后正式版的实现基础，当前交付仍为开发候选。
