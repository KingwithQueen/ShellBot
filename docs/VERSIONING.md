# 版本递增规则

从 1.1.0 起，产品版本固定为 `A.B.C`：A 为正整数，B/C 各为 0～9 的一位数字，不加预发布或构建后缀。A 的递增计算使用任意精度整数，不人为设置最大值。

每次优化递增 C；C 从 9 进位时归零并递增 B；B 从 9 进位时归零并递增 A。例如 `1.1.8 → 1.1.9 → 1.2.0`，`1.9.9 → 2.0.0`。历史版本 `1.0.10` 保留原名，本次按指定版本升级至 `1.1.0`。

在源码根目录运行：

```powershell
.\scripts\version.ps1 -Check
.\scripts\version.ps1 -PrintNext 1.9.9
.\scripts\version.ps1 -Next
```

`Check` 只检查版本头、Windows 数值资源、CMake 和 README 标题的一致性；`PrintNext` 只计算而不写入。`Next` 同步这些位置，并更新 README 中当前版本的引用。指定版本可用 `-Version 1.1.0`。发布说明、变更内容与验收记录仍需按实际工作更新。构建和 Windows 正式打包入口会先执行一致性检查，拒绝两段低位出现多位数等无效版本。

完整版本以 `SB_VERSION` 及 Windows FileVersion/ProductVersion 字符串为准。Windows 固定数值资源的每段受系统 WORD 格式限制：第一段存 A 的低 16 位，第四段存下一组 16 位，第二/三段存 B/C。不会因这一系统格式限制截断完整产品版本字符串，也不把它当作 A 的产品上限。常规版本（A≤65535）仍为 `A,B,C,0`。历史文件及发布包不会被递增脚本改名。
