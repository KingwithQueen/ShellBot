# ShellBot 第一阶段开发计划

更新日期：2026 年 10 月 10 日。当前迭代顺序以 [开发计划](DEVELOPMENT_PLAN.md) 为准，权限边界以 [项目权限与执行身份](EXECUTION_PERMISSIONS.md) 为准。dev.8 已完成 M1 项目配置、统一策略及显式迁移，本机验证见 [实现记录](IMPLEMENTATION_STATUS.md)，新项目运行仍待 M2/M3。下文保留已有第一阶段里程碑及实际验收。基础工程、阅读工具、代理接入、本机审批、创建、覆盖、局部替换、私有备份和审计已实现；dev.7 加入普通用户和管理员后台任务，本机 Windows 11 启动、输入输出、取消和代理复用已验收；dev.6 管理员身份基础层已在 Server 2025 验收。跨账户提权、完整受控隔离、规则、远程审批和目标客户端工具验收仍待完成。OAuth、隧道管理和域名检查不作为当前开发前置条件。

本阶段制作 Windows 10 和 Windows 11 x64 的 WinShellBot 基础服务。完成后，用户可以从实际 MCP 客户端授权连接电脑、操作测试目录内的文本文件、查看图片、执行授权程序，并查询或取消后台任务。

WinShellBot 优先使用 Windows 原生能力。通用协议、参数、权限、任务和结果逻辑保存在独立 C 核心中，平台实现使用清晰的接口，兼顾以后 Linux 和 macOS 的移植。本阶段不实施其他平台发行。

## 已确认的决定

| 项目 | 决定 |
| --- | --- |
| 名称 | ShellBot，Windows 项目为 WinShellBot |
| 主平台 | Windows 10 和 Windows 11，x64 优先 |
| 实现语言 | 自有通用核心使用 C17；必要的第三方原生组件按接口隔离 |
| 初期构建 | 沿用现有 Visual Studio 解决方案和项目，先不并行维护 CMake |
| 模型职责 | 模型服务负责推理，ShellBot 负责执行；本阶段不内置聊天代理循环 |
| 接入 | stdio 与 Streamable HTTP；只监听本机端口，已有环境负责域名和隧道；外部地址配置可选，不开发 OAuth 或 cloudflared 管理 |
| 目录 | 配置支持多个授权目录，分别设定读写范围；不硬编码唯一工作目录 |
| 项目管理 | 优先实现项目配置、普通权限管理器和每项目独立工作进程；各项目独立 MCP 地址、凭据、任务及审计；最小管理界面后续交付 |
| 运行身份 | 受限、当前账户普通权限、管理员身份与审批方式解耦；管理员代理逐项目授权复用，启动 UAC 一次不授予其他项目；系统服务以后扩展 |
| 操作审批 | always、workspace_auto、never 三种模式独立配置；不改变目录、只读和执行身份上限 |
| 目录外访问 | 默认拒绝；所有者可授予额外目录只读/读写或当前账户可访问范围，不因批准命令自动扩权 |
| 管理方式 | 先做项目配置和命令行启停，再做最小项目管理界面；所有者审批入口与 MCP 控制权限分离 |

初始工程是空的 Visual Studio 控制台项目，默认配置使用 C++20。目前已切换为 C17，加入通用核心与 Windows 实现，Debug/Release x64 能构建运行。项目主分支已切换为 main，本地和远端 master 已删除。

## 第一阶段功能

| 工具 | 预期行为 |
| --- | --- |
| host_info | 返回系统、程序版本、实例身份和基本运行状态，不泄露凭据 |
| host_capabilities | 返回实际可用的工具、权限、目录、协议与依赖状态 |
| fs_list | 列出授权目录内的条目，支持范围与分页 |
| fs_read | 按行或字节预算读取文本，标明编码与截断信息 |
| fs_search | 在授权目录内查找文件名或文本内容，限制结果和时间 |
| fs_write | 受控创建或覆盖文本，支持预期哈希与明确的覆盖选项 |
| fs_patch | 对文本进行有前置条件的局部修改，冲突时不覆盖原文件 |
| image_view | 查看 PNG 与 JPEG，以原生 MCP image 内容返回，并控制响应大小 |
| task_start | 启动明确授权的程序与参数，耗时工作返回任务编号 |
| task_input | 向允许交互且仍在运行的任务输入内容 |
| task_status / task_output | 分别返回任务状态和退出信息、按原始字节游标读取有界 stdout/stderr |
| task_cancel | 停止本人任务并清理所属进程树，报告真实取消结果 |

权限申请、审批状态与授权撤销是核心管理能力，不把可以批准自己的操作开放为模型工具。对具体客户端可用的 elicitation 形式，在互操作验证后接入；未支持时提供本机审批或身份校验后的网页审批入口。

基础版支持中文路径和 Unicode。文本编码采用明确的识别与转换策略，对不确定编码给出信息或要求选择，不悄悄损坏原文件。初期不承诺全部图像格式、图像编辑或大规模内容索引。

## 第一阶段既有里程碑

### 第一步 工程和运行骨架

保留现有解决方案与工程身份，明确 C17、源码编码、警告设置、Debug 与 Release x64 产物位置。建立 C 核心与 Windows 接口边界，接入最少依赖，提供配置加载、配置错误提示、版本、实例身份和脱敏日志。

默认回环监听，支持显式数据目录，防止同一目录被多个写入实例同时占用。stdout 在 stdio 模式下专用于协议，诊断输出走 stderr 或日志。

通过条件：在开发机完成 Debug 和 Release x64 构建；配置有效时启动、无效时给出明确错误；启动与退出能够清理资源。构建时无需启动任何公网隧道。

### 第二步 MCP 接入和阅读工具

接通 stdio 与 HTTP，通过协议适配器支持实际目标客户端的必要版本。先实现主机状态、能力报告、目录列表、文本读取搜索与图像查看。

HTTP 监听回环地址，使用现有 bearer；未填写域名也接受已有代理的合法 Host/Origin，填写 public_url 时启用地址限制。请求、输出、超时和并发有上限，不宣称未实现的协议能力。

通过条件：诊断客户端能列出并调用工具；文本包含中文时读取正确；图像结果使用标准 image 内容块；错误参数、未知工具及范围之外的路径被拒绝。记录测试客户端实际使用的协议版本。

### 第三步 外部访问地址和目录策略

用户已确认暂缓 OAuth 和 cloudflared 管理；已有隧道已在其他程序上验证，本程序只需本机端口。默认不要求填写或检测域名，接受合法代理请求头并继续要求 bearer。http.public_url 或 --public-url 是可选白名单限制和 public_endpoint 报告能力，管理入口与 MCP 路由分离，见 EXTERNAL_ACCESS.md。

实现多个授权目录、目录读写权限、项目和工作目录标识、授权撤销与基础审批记录。目录选择不自动增加权限；客户端给出的根目录列表不能直接当作主机所有者的许可。

待审批记录绑定主体、规范化目标、操作和参数摘要及有效期。接受、拒绝、取消与过期有明确结果；模型不能通过 approved=true 等参数自我授权。客户端交互机制只在确认客户端支持后使用。

通过条件：本机模拟代理转发时无需填写域名，错误 bearer 被拒绝；填写 public_url 后仅允许明确地址；至少两个目录及不同读写规则得到验证。检查重解析点、路径边界及审批参数绑定。OAuth 和域名检测不是本阶段完成前置条件。

### 第四步 文件修改与后台命令

加入受控文本写入和修改，使用预期哈希与目标平台支持的安全替换，写入冲突保留原文件。加入参数化程序启动、标准输出和错误读取、必要的交互输入、超时和取消。

命令能力默认关闭，项目的审批模式和执行身份分别配置；文件范围、管理员使用许可和工具开关也独立检查。工作目录项目可自动读写目录内文件而逐次批准命令，完整权限项目可选择范围内自动执行并另行允许管理员能力。管理员代理启动时 UAC 授权一次，只服务已获所有者授权的项目；不能因一个项目已提升就授权其他项目。MCP 请求不能扩权，具体边界见 [项目权限与执行身份](EXECUTION_PERMISSIONS.md)。命令 cwd 不是沙箱，严格工作目录限制必须经过受限执行验收。

Windows 使用进程树归属和清理机制，保存任务状态及输出位置。程序退出或崩溃后按策略清理本人子进程；重启时识别中断任务，不自动重跑命令。修改和命令请求支持幂等键，重试查询既有任务；无法确认副作用时返回不确定状态。

通过条件：文件修改成功、冲突不覆盖；长任务可查询和取消；取消后本人子进程清理完成；连接中断后能查询原任务；重试不重复启动程序。分别验证三种审批模式及文件范围，已允许项目在启动代理授权后复用管理员执行，未允许项目仍被拒绝；普通任务不误继承提升令牌，受限任务不能自批、扩权或访问未授权资源。逐次审批可由另一台设备的所有者完成。验证输出超限、错误退出、中文路径及文本编码。

### 第五步 客户端工具验收和候选交付

检查本机服务和实际客户端工具调用，stdio、本机 HTTP 或已有外部环境均可作为接入方式。不管理或强制检查外部域名、DNS、隧道进程、凭据和网络配置。

第一阶段提供主机启动停止、状态与失败报告；隧道安装、管理和自动恢复按当前范围暂缓，长期运行优化和自动更新留待后续。

制作独立 Windows x64 便携候选包，记录源码身份、程序与依赖版本、校验信息和配置样例。发行目录不包含用户数据、凭据、日志与测试产物，不要求用户安装 Node.js、Python 或开发环境。

通过条件：从实际目标客户端完成文本读取修改、图像查看和任务操作，确认模型实际获得图像。本机自检与客户端成功分别记录，不以域名探测作为功能开发门槛。
