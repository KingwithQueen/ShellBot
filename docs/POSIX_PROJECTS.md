# Linux / macOS 完整项目配置、远程审批与数据迁移

第九阶段。Windows 继续使用原有 Win32 界面、管理器和数据格式。本说明用于 Linux GTK / Mac Cocoa 开发版。

## 完整项目设置

在项目页“添加 / 编辑”打开六页原生表单：

- 基本：稳定地址标识、项目数据位置、凭据引用、项目启用、中文显示名称、默认工作目录和随后台启动的项目选择。
- 目录：分别增删多个工作目录和额外授权目录，逐项设置标识、路径和只读；默认工作目录填写工作目录标识，留空使用第一个工作目录。
- 权限：always / workspace_auto / never、配置目录或当前账户文件范围、其他账户文件只读、命令开关、restricted / current_user、独立管理员许可和精确运行文件。
- 工具：逐项选择全部 37 个工具；工具开关不代替文件、命令或桌面授权。
- 桌面：查看、键鼠、剪贴板读写、租约上限和紧急停止功能键。
- 配额：审批期限、审计预算、任务数、任务记录、任务输出预算、超时及内存配置。Intel Mac 使用进程组物理占用采样，Linux 限制单条命令地址空间，具体边界见 POSIX_BACKEND.md。

保存前停止后台。表单先校验，后台保存时再核对打开表单时的配置 SHA-256，拒绝覆盖后来发生的配置变更；已有配置产生独立备份，权限变更增加策略版本。保存不会立即执行命令或连接桌面。已有项目的地址标识和凭据引用保持固定；数据位置通过专用迁移入口变更。更改显示名称不会改写 MCP 地址。

“启动后台”按各项目明确保存的自动启动选项启动项目；默认不选。登录自启仍只打开管理窗口，不隐式运行后台。独立服务的启动项目列表仍由服务安装参数指定，不读取管理窗口的选项。管理员许可只允许使用所有者显式启动的 root 代理；勾选、保存或启动普通后台均不弹窗提权。“管理员”页另有明确启动系统授权和结束会话入口，见 [本机管理员管理](POSIX_DESKTOP.md)，不修改 sudo 配置。

## 远程所有者操作审批

在连接设置启用“远程所有者操作审批”，保存后启动后台。程序生成独立随机所有者凭据，以 `owner.sealed` 加密保存；“复制独立审批凭据”是明确的本机操作，将其放到系统剪贴板。凭据不会显示在项目详情、审批 URL、启动参数或日志中。系统剪贴板本身属于当前账户信任范围。

审批页面是 `http://127.0.0.1:端口/owner`，已有 HTTPS 代理可转发同一端口。另一设备访问已有公网地址的 `/owner`。使用独立所有者凭据连接，选择项目、普通或管理员身份，查看完整请求后批准、拒绝或撤销。允许后由客户端原样重试；页面不代替客户端执行操作。

手动配置注册表时，`gateway.owner_token_env` 启用该入口；变量名与项目引用必须独立。可以在环境中提供独立的 32～256 字节可见 ASCII bearer，或配合 `--credential-store` 使用此管理器已生成的加密所有者凭据。值与任何项目 bearer 相同、存储损坏或环境与存储冲突时拒绝启动，不静默替换。省略字段时所有者路由关闭。

`GET /owner`、`/owner.js`、`/owner.css` 仅提供页面壳。`POST /owner/api` 在读正文、选择项目之前验证独立凭据；项目 token 和 OAuth token 都不能审批。拒绝跨源请求、查询参数、重复安全头、非规范路径和分块正文，正文最多 64 KiB；响应禁缓存并限制页面脚本、嵌入和引用来源。

接口仅接受 projects、list、inspect、approve、deny、revoke 和 history。决定必须包含查看到的摘要、运行实例和策略版本；不接受配置修改、项目启停、桌面连接、OAuth 批准或管理员代理启动。普通和管理员审批池独立，管理员审批只转发到已经匹配并绑定的 root 代理；没有代理时明确失败。审计 actor 固定为 remote-owner。MCP pending 响应提供无凭据的审批链接；共享协议核心中已有的 URL elicitation 继续按客户端声明生效。

## 项目和应用数据位置迁移

项目页的“迁移项目数据”只移动所选项目 Data；连接设置的“迁移应用数据”移动整个管理窗口数据目录，包括配置、管理器、内置项目 Data 和内部运行资源。目录外的项目 Data、工作目录、运行资源和独立密钥文件保持原位置。两种迁移均只支持同一系统、同一 UID，不读取 Windows Data，也不提供跨机器或跨账户解密。

1. 停止后台及所有使用这些 Data 的独立进程。迁移需要取得管理器和各项目的独占锁。
2. 应用迁移前取消登录自启；独立后台服务先卸载，迁移后用新的活动注册表和管理器 Data 重新安装。旧服务路径不能继续运行旧副本。
3. 选择空的、当前账户拥有的私有目录。父目录须已存在；目标权限为 0700，不能与源、其他 Data、授权文件目录或密钥目录重叠，也不能使用路径别名。显式密钥文件须位于应用数据目录之外；root 管理员状态仍由管理员独立管理。长 Data 使用私有短运行时通信目录，不再受 Unix socket 地址长度限制；仍须给派生状态文件保留系统原生路径预算。
4. 后台队列通过目录句柄复制，拒绝符号链接、硬链接、其他账户文件、特殊文件及 set-id。逐文件重新读取目标并核对 SHA-256，同时核对源对象未变化。最多 100000 项、深度 64、合计 8 GiB；不使用 shell 复制命令。
5. 当前项目 bearer、独立所有者凭据和 OAuth 状态在内存中验证、按新命名空间重新加密；不落盘明文。精确重绑匹配的原项目数据身份，保留授权期限、撤销状态、刷新代数和防重用状态，不给其他项目或新凭据继承旧连接。历史恢复密文保留在原目录，不作为新位置的自动回退。
6. 全部准备好后，单个 `active.json` 选择相互匹配的新注册表与管理器存储。应用迁移另在原入口留下私有 `relocation.json`；重新打开原入口会跟随它。源 Data 的迁移保护记录阻止旧服务或旧项目命令重新启动旧副本。旧数据不删除，旧任务、输入、租约和审批许可不重放。

“取消迁移”请求后台停止复制，发布前取消不切换活动位置。失败时保留源数据和目标准备文件，不覆盖目标、不自动删除或重试。若进程在最终准备阶段意外中断，原位置的保护记录会阻止启动；重新打开管理窗口，核对后使用“取消未完成的迁移”恢复原位置。此操作须匹配当前迁移编号，只取消尚未发布的准备，不撤销已发布迁移，也不删除准备文件。已发布位置若同步确认失败，会保留保护并报告错误，须先检查当前活动位置。

不要手工移动加密 Data、改写活动文件或启动旧目录；原目录是恢复材料，不是第二份独立运行的数据。迁移成功后先重新启动后台并核对项目和客户端，再决定如何保管原目录。应用移到新位置后可重新启用登录自启。

## 验证边界

本地 `tests/posix_profile.py` 通过原生控制器、真实回环 HTTP 和原生文件系统验证复杂配置、过期表单、独立所有者认证、决定绑定、历史、OAuth 续期、项目/应用迁移、链接拒绝和恢复；测试源按仓库约定只保留本机。`scripts/build-posix.ps1 -WithTests` 包含该套件；`-TestScope project-profile` 只运行此专项，不能代替完整回归。

自动夹具使用独立显式私有密钥、模拟客户端和临时目录。真实浏览器/公网代理、实体 GUI 操作、系统钥匙串升级 ACL、实际 root 代理审批、重启登录、突然断电和长期运行仍另行验收。人工验收暂缓不等于这些场景已通过。
