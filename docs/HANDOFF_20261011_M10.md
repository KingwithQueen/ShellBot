## 实现范围

新增 core/tools/document.c 及 Windows document.h / document.c / pdf.c / office.c，提供 document_info、document_read、document_preview。项目工具登记 30 个，旧单实例 16 个；桌面范围固定为索引 15–26，避免新增文档被误判为桌面功能。接入既有文件物理对象、范围、只读、审批、audit、actor 和真实管理员代理。

PDF 以内存方式使用固定 PDFium 157.0.8086.0 无 V8 / XFA DLL，读取真实页数、Unicode 文本、页面 PNG；无 OCR、密码输入或交互表单环境。Office 根据 OPC 关系解析 DOCX 正文、XLSX 工作表存储值及 PPTX 幻灯片文本，支持普通/strict 命名空间、非标准部件路径和 Unicode。XLSX 不重算公式、不格式化日期；未接入 Office 图片、图表、页眉/脚注/备注或完整版面。Office PNG 明确标注为“内容预览（非原始排版）”，不可当作 Word 原始页码或幻灯片视觉排版。

用户确认优先 DOCX / XLSX / PPTX，DOC / XLS / PPT 和宏格式提示转换。格式、源/结果 SHA-256、实际尺寸、单元数和截断状态随结果返回，源文件不变。源 32 MiB、单元提取 1 MiB、每页 64 KiB、预览 2 MiB；PDF 最多 4096 页，Office 工作表/幻灯片最多 256 单元，信息列表最多 128。XML DTD/外部实体关闭，Office ZIP 最多 2048 项、单项展开 8 MiB、总展开 64 MiB，并核验关系和无宏主文档类型。完整参数/限制见 [DOCUMENT_READING.md](DOCUMENT_READING.md)。

审批前只固定文件元数据，不解析正文、页数或工作表名；同许可只允许同 unit / 参数 / 源版本沿 next_offset 继续。大图回执超出 512 KiB 时在原有效许可内重算且逻辑预算只计一次。document_preview 的完整名称为 16 字符，原审批 tool[16] 越界已修正为 tool[32] 并增加长度检查。正常项目客户端同时保留文档语义与统一权限说明，避免丢失 Office 预览限制。

自有代码仍为 C17；不需要 Office、Python、Node.js 或 .NET。third_party/pdfium 保留 x64 / Win32 DLL、两个公开头文件、版本/参数、provenance.json、外层 MIT 和全部 17 项上游/依赖许可。发布者 bblanchon 独立于上游 Google/Foxit，DLL 非本仓库自行构建；固定归档 SHA 与发布元数据一致，未宣称发布签名/构建证明核验。默认构建复制同架构 DLL，运行时核对固定 SHA 并持有读句柄；不存在/篡改明确拒绝 PDF，Office 仍可用。Win32 仅保留依赖，未做本轮产品构建验收。

## 失败保留与验收边界

最初 x64-Release-m10-initial/second/third/fourth/fifth.json 及对应夹具保留：新增工具误分类桌面；XmlLite EndElement 深度与删除修订状态；共享字符串复用污染后一个单元格；分页夹具错误期待“好”而实际 4 字节为“好 ”；审批工具名越界。前三者/第五者修正产品，第四者修正夹具。sixth/seventh 普通通过报告也保留，最终报告另外保存。

第一轮旧图像回归使用硬编码 dev.16，产品已为 dev.17，导致“host survives bad image crc.png”失败；两份原报告为 x64-{Debug,Release}-m10-image-version-initial.json。仅更新测试版本后通过。工具说明修正前的完整报告及 Debug/Release 主程序保留在 `build/validation/m10-pre-description`，包括早一轮 351 项真实 UAC 记录，最终 355 项另有匹配摘要。

首编译使用了 SDK 不存在的 XmlLite SignificantWhitespace 枚举，改用有效枚举；没有独立首编译日志。PDFium 归档下载曾遇到截断/摘要不符，重试后完整归档与发布 SHA 一致才引入，失败字节未引入或执行；原始失败日志只存在工具输出，收据不伪造文件。

历史 HTTP close 偶发重置仍未修复，核心采用 SkipCloseProbe；部分旧 hardlink 夹具因当前文件系统不可用跳过。没有重跑桌面输入/剪贴板、托盘/物理停止或管理员全部旧专项。独立 Windows 10 / Server 2025、另一设备/代理、真实 MCP 客户端、多屏/锁屏/RDP、完整 Office 排版和 OCR 仍分别待验收。普通文档专项通过 stdio 和管理器工作协议；共同 HTTP 网关由旧功能回归覆盖，本轮未把文档工具的真实远端客户端调用当作已验证。

解析在既有后端进程内，预算不等于独立解码进程/硬超时或任意恶意 PDF 的精确 CPU/内存限制。当前现有候选打包脚本仍锁定 M7，尚未包含 M8–M10 新门槛、PDFium DLL/完整许可；不降低门槛打包、不复用 dev.14 收据。
