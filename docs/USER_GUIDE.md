# ShellBot 使用说明

## dev.28：项目优先排版、长期授权与便携数据（当前预览）

完整解压便携测试包，双击 **ShellBot.exe**。首次直接显示项目管理窗口，空列表可以立即新建项目。使用普通 Windows 账户权限即可；配置、启动、端口、令牌和退出均在界面完成。

### 管理界面

使用原生 Windows 菜单与系统控件。顶部右侧管理连接、客户端授权和数据位置。左侧是项目列表，新建按钮位于列表标题旁，刷新按钮位于列表下方。右侧显示所选项目名称与状态，项目设置、启停/暂停/恢复及详情都在同一区域；右侧下方复制地址、项目令牌或查看诊断。管理员代理和审批令牌位于“工具”菜单，完整地址/令牌命令也可从“连接”菜单选择。数据路径移到底部。

“视图 → 经典布局”可随时切回 dev.27 排版，“视图 → 项目优先布局”返回新版。切换保留当前项目、详情选区和阅读位置，不修改项目权限，也不重启项目。排版选择只在本次窗口中保留，下次打开默认使用项目优先布局。此次是可对照试用的排版预览，说明见 [排版预览](LAYOUT_PREVIEW_20261021.md)。

`F5` 刷新，`Ctrl+N` 新建项目，`Ctrl+E` 打开项目设置，`Ctrl+L` 打开客户端授权。菜单支持 Windows 的 Alt 快捷导航。Tab 顺序跟随当前布局的操作分组；项目列保留可读宽度，必要时横向滚动。

项目、连接和数据位置表单可按 Enter 执行默认保存操作，按 Escape 取消。客户端授权窗口默认 Enter 关闭窗口，不会自动同意连接；批准仍需明确选择“允许此连接”。

自动刷新保留文本选区、阅读位置和诊断。短暂连接失败保留最后一次内容，并在底部提示状态暂未更新；此时项目操作暂停可用，恢复连接后自动更新。切换项目后，稍晚返回的旧项目诊断不会覆盖当前详情。手动刷新会从诊断返回项目摘要。

“文件 → 退出并停止全部项目”和托盘退出执行相同的关闭流程。窗口右上角关闭仍收进托盘。

### 新建项目

1. 点击“新建项目…”。
2. 填写项目名称，支持中文。地址标识可在创建前修改，只允许 1～63 个英文字母、数字、下划线或连字符；创建后保持固定。
3. 默认项目目录位于程序旁的 `Data\Projects`。可以改为独立、可写的非 C 盘本地空目录，例如 `D:\开发\ShellBot\测试项目`。
4. 默认工作目录为该目录下的 `Workspace` 子目录。存储根目录保存内部配置，`State` 保存运行数据；工作目录用于 MCP 操作文件。
5. 按需要设置工作目录只读和审批方式。“权限、目录与工具…”可设置更多目录、具体工具、命令身份及桌面权限。
6. 点击“创建项目”。项目立即出现在主界面列表；默认勾选“随管理界面启动此项目”，创建后即启动。取消该选项时，可在列表中手动启动。

项目凭据由程序生成，并与项目配置一起通过当前 Windows 账户加密保存。右侧“项目令牌”或“连接 → 复制项目令牌”用于客户端认证；不需要手动设置环境变量。

### 端口与客户端连接

在主界面点击“连接设置…”，填写本机监听端口，即已有隧道的本机目标端口。只监听 `127.0.0.1`。公共地址为可选项，可填已有 HTTPS 域名，用于生成公共链接。应用连接设置会提示停止活动任务并重新建立网关；项目按“随管理界面启动”设置重新启动，旧任务不会重放。

在“连接设置”填入 HTTPS 公网域名地址，例如 `https://你的域名`，不要添加 `/projects/...` 路径。OAuth 会自动启用，域名和隧道继续使用你已有的配置。当前数据目录中保存的 HTTPS 公共地址和项目会直接复用。

1. 选中运行中的项目，点击右侧“公网地址”或“连接 → 复制公网地址”。例如标识为 `ShellBotTest` 时，地址为 `https://你的域名/projects/ShellBotTest/mcp`。
2. 在 ChatGPT“添加自定义 MCP 服务器／创建为插件”中粘贴地址，认证选择 **OAuth**。使用自动／动态客户端注册（DCR）；无需手动填写客户端 ID、客户端密钥或项目 token。若客户端询问 scope，可使用 `mcp offline_access`。
3. 客户端打开授权页，显示申请编号，并等待你在待测电脑确认。
4. 打开 ShellBot 管理界面的 **“客户端授权…”**，选中“待确认”申请，核对浏览器中的编号、项目和完整回调地址。默认勾选 **“长期授权，直到手动撤销”**，点击“允许此连接”。客户端名称由对方提供，不能单凭名称判断来源。取消勾选可使用 30 天限时授权。
5. 浏览器返回客户端，完成安装。之后请求携带独立的访问凭据，不需要将 token 粘贴到对话或 URL 中。

访问凭据每次有效 15 分钟，由客户端自动续期。长期授权没有固定到期日，首次人工确认后无需定期回到待测电脑；重启、迁移目录和修改项目权限后继续有效。它允许客户端使用项目当前权限，包含之后新增的权限，每次工具调用仍受当前目录、工具、任务身份和审批规则检查。限时授权最长 30 天，实际权限变化后仍需重新授权。

正常续期不会立即作废尚未到期的访问凭据，原到期时间保持不变。续期凭据每次轮换；重复使用已消费的旧续期凭据会撤销整条连接。退出管理器会停止所有项目；重新打开后可继续使用已保存的授权。尚未完成的授权申请和授权码在重启后失效，需要重新连接。

“客户端授权…”可查看授权方式、连接状态和撤销原因，也可拒绝申请、撤销项目连接或移除登记客户端。登记不代表已经授权。撤销立即禁止后续请求，重启后仍生效；它不撤销已执行的操作或停止已开始的任务，需要结束任务时请停止项目。移除客户端会终止其所有连接。删除项目后用相同标识新建项目，不能继承原长期授权；更换项目凭据、更换公网域名、清除凭据或更换 Windows 账户后需要重新连接。

窗口底部显示本次运行中最近一次认证失败原因，成功连接不会清除此历史提示。旧续期凭据重用导致的撤销原因会加密保存。该诊断不包含访问令牌、续期凭据或回调参数。长期授权是 ShellBot 的服务器端授权策略；若客户端删除连接、丢失凭据或要求再次登录，仍需从客户端重新连接，ShellBot 不能代替客户端保存凭据。

升级前从托盘退出旧版，并在非 C 盘备份原数据目录。dev.26 可读取旧版 v1/v2 OAuth 存储，后续保存为 v3。旧连接保留原限时规则，不会自动变成长期授权。需要长期连接时，升级后从客户端重新连接一次，并在本机勾选长期授权。旧的失效记录可手动撤销；无需清空所有数据。回退旧版时须同时恢复更新前的数据备份，旧版不能读取 v3。项目文件与凭据请保留。

OAuth 仅解决客户端连接认证，不扩大项目的文件范围、工具、任务身份或管理员权限；原有逐次操作审批继续生效。只有本机所有者管理界面和受保护的本机管理通道能批准 OAuth 连接，远程所有者审批页面不能替代此步骤。

兼容客户端仍可使用 `Authorization: Bearer 项目令牌` 请求头和“复制项目令牌”。URL 查询参数不接受 token；ChatGPT 插件请选择 OAuth，避免选择“无需身份验证”。参见 [OpenAI 自定义 MCP 说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)及 [认证说明](https://developers.openai.com/plugins/build/auth)。

需要审批时，使用工具返回的所有者审批地址，或在浏览器打开 `http://127.0.0.1:端口/owner`。“复制审批令牌”取得独立所有者凭据；它与 MCP 项目令牌用途不同。隧道、域名映射和 MCP 客户端安装沿用已有环境。

### 修改项目及存储目录

选中项目，点击“项目设置…”。可修改中文名称、存储位置、工作目录、审批、自动启动及高级权限。地址标识和令牌保持稳定。

实际权限或目录变化会停止该项目并按原运行状态重新启动；未改动保存或只修改显示名称、自动启动选项不重启工作进程。其他项目继续运行。存储目录变化时，选择新的空目录，程序复制项目配置和数据、逐文件校验 SHA-256，成功后切换。存储目录内的工作目录和运行资源路径随迁移调整，外部目录仍保留原路径。原目录保留用于恢复，旧执行许可不会恢复，任务不会重放。

自动刷新只更新发生变化的项目内容；不会周期性禁用再启用按钮。阅读位置、文本选区和诊断视图继续保留。

保存失败时保留原配置及原目录。因取消或失败而留下的部分目标文件会保留供检查；请按提示选择其他空目录或处理已复制的目标。项目目录之间、项目数据与授权工作目录之间的冲突会被拒绝。

### 关闭和退出

点击窗口关闭按钮或 Alt+F4，窗口收进系统托盘，项目和后台任务继续运行。单击托盘图标重新显示管理窗口；也可以再次双击 ShellBot.exe，激活同一实例。

在托盘图标上右键，选择 **“退出 ShellBot（停止全部项目）”**。退出会停止本实例所有项目、后台任务和 HTTP 网关。若目录复制尚在进行，退出会取消迁移并保留原索引与全部源文件；已完成的配置提交保留完整新版本。托盘暂不可用时窗口保持可见，并等待托盘恢复。

重新打开后读取已保存项目，按每个项目的自动启动选项启动工作进程。历史任务、审批、审计和备份保留；旧任务不会重新执行。

管理器后台自动刷新会保留右侧详情的选区和阅读位置。查看诊断时，自动刷新继续更新左侧状态并保留诊断内容；点击“刷新”返回项目详情，切换到其他项目时从新项目的开头显示。

### 便携数据位置与迁移

默认应用数据全部放在 **ShellBot.exe 所在目录的 `Data` 文件夹**，不再读取或创建 LocalAppData、用户“文档”目录中的 ShellBot 数据。`Data\Desktop` 保存项目索引和加密凭据，`Data\Desktop\Manager` 保存管理器及 OAuth 状态；默认项目在 `Data\Projects`，各自保存配置、`State` 和 `Workspace`。

主界面的 **“数据位置…”** 可以修改应用数据目录。选择独立的非 C 盘空目录后，程序停止全部项目，先复制并逐文件核对 SHA-256，再更新内部项目路径并保存新位置。完成界面会列出原位置和新位置；点击“完成并退出”，重新打开 ShellBot 后使用新位置。确认新位置正常后，可手动删除旧目录。复制、校验或位置设置保存失败时保留原配置和目录；目标中的已复制文件也保留供检查。

位置设置保存在程序旁的 `ShellBot.storage.json`，默认位置不需要该文件。修改位置后，这个小文件必须与程序一起保留。程序目录在 C 盘或不可写时，会明确询问非 C 盘数据位置；无法保存位置设置时会提示下次启动需要重新选择，不会写入 C 盘或悄悄改用系统目录。建议将整个程序解压到可写的非 C 盘目录。

使用默认 `Data` 时，退出后可以移动整个程序文件夹。重新打开会更新内部路径。另行指定的应用数据目录保持独立；另行指定的项目存储目录在“项目设置…”中迁移。应用数据和项目存储路径均拒绝 C 盘，以及实际指向 C 盘的目录别名；不限制按项目权限明确授权的 C 盘文件操作。

日志、审计、任务状态、图片与文档产物均使用所选数据目录。ShellBot 和工作进程的临时、缓存及应用配置环境目录放在数据目录的 `Runtime` 子目录；受限进程只获得自己的临时目录权限。受限命令也不在 C 盘创建沙盒配置目录，并继续验证原有隔离边界。

OAuth 状态仍由当前 Windows 账户加密。目录移动不会解除账户绑定；不能把加密凭据当作可跨账户使用的普通便携文件。路径变化会增加相关项目的策略版本，旧执行许可和限时 OAuth 连接需要重新授权；长期 OAuth 连接与客户端登记保留。每次操作按更新后的目录权限检查，已有任务不会重放。

### AdGuard 与本地代理

本机对照已确认：AdGuard 的 localhost 过滤会破坏 TCP 半关闭，独立原生探针和未修改的旧版 ShellBot 也会受影响。dev.24 加固了关闭流程，错误响应及时返回，随后有界排空连接；这不能修复过滤驱动本身。本轮回归继续保持 AdGuard 服务运行与 localhost 过滤开启，由用户为固定路径的 Debug/Release 主程序、独立探针及专用验收客户端添加应用排除。准确环境和历史开关对照见包内 `validation/environment.json` 及原始观察记录。

关闭 localhost 过滤可能影响浏览器经本机代理的网页过滤。需要本地代理过滤时，可保留 localhost 过滤，仅对 ShellBot 相关程序添加排除，并分别复验 MCP 连接与浏览器过滤。本轮四项固定路径排除后，独立探针及严格 EOF/响应回归通过；浏览器、代理和系统 Python 未加入本轮排除，其实际网页过滤效果没有独立测试。正常使用可把程序放在固定的非 C 盘目录，在 AdGuard 高级设置的“过滤时按完整路径排除应用”中追加该目录下 `WinShellBot.exe` 的完整路径；保留已有项，多项以分号分隔。升级时更新同一路径下的程序，避免白名单因目录变化而失效。独立探针和专用客户端属于开发回归工具，不随正式程序分发。该选项见 [AdGuard 高级设置说明](https://adguard.com/kb/zh-CN/adguard-for-windows/settings/app-settings/advanced-settings/)。

当前版本的本机功能、严格 EOF、便携迁移、OAuth 和解压验证以包内 validation 收据为准。历史失败原样保留，不能将单次通过或跳过 EOF 的测试当作稳定性结论。真实 MCP 客户端、新版本实际管理员和独立机器仍由各自专项验收。

## 1. 准备程序和目录

本地候选包位于仓库的 `dist/ShellBot-0.1.0-dev.14-windows-x64-candidate-20261011-090856.zip`。解压到自己的程序目录，例如 `D:\ShellBot`。保留同目录的 `WinShellBot.exe` 与 `ShellBot-SandboxProbe.exe`；后者用于受限任务后端的启动检查。

源码构建的 dev.19 还会生成旁置 pdfium.dll 及 ShellBot-Launcher.exe，分别用于 PDF 和托盘登录启动；保留同架构文件及名称。Office 功能不要求安装 Microsoft Office。当前未制作新的 dev.19 候选包。

准备三个相互分开的位置：

| 用途 | 示例 | 保存内容 |
| --- | --- | --- |
| 程序目录 | `D:\ShellBot` | 程序、说明、实际配置 |
| 工作目录 | `D:\ShellBotWorkspace` | 允许模型访问的文件，必须预先存在 |
| 项目数据目录 | `D:\ShellBotProjects\example\state` | 私有审计、审批和任务历史、修改备份 |

项目数据目录不要放入授权工作目录；多个项目的数据目录不能相同或互相包含。管理器使用独立数据目录，包内启动脚本默认采用程序目录下的 `Data\Manager`。保留现有数据，首次试用使用新的目录。

复制包内 `manager.example.json` 为 `projects.local.json`，编辑以下两项为自己的绝对路径：

```json
"data_dir": "D:/ShellBotProjects/example/state",
"workspaces": [{ "id": "workspace", "path": "D:/ShellBotWorkspace", "read_only": true }]
```

这是配置片段，应修改原文件中的对应项，保留其余结构。示例项目 id 为 `example`；默认只读、每次文件访问审批，命令和管理员能力关闭。配置说明及双项目样例见 [项目配置](PROJECT_CONFIGURATION.md)。

在普通 PowerShell 中校验配置：

```powershell
Set-Location 'D:\ShellBot'
.\WinShellBot.exe --validate-projects .\projects.local.json
```

校验只检查配置，不启动项目。工作目录是否存在、实际权限和后端能力还会在项目启动时核验。

## 2. 启动管理器和窗口

在同一个普通 PowerShell 中分别生成项目凭据和所有者凭据：

```powershell
$env:SHELLBOT_EXAMPLE_TOKEN = (& .\WinShellBot.exe --generate-token)
$env:SHELLBOT_OWNER_TOKEN = (& .\WinShellBot.exe --generate-token)
.\Start-Manager.cmd
```

环境变量名必须与配置中的 `token_env` 和 `gateway.owner_token_env` 一致。每个启用项目的凭据值都必须不同，所有者凭据也独立。保管好这些值：项目凭据用于 MCP 客户端，所有者凭据用于审批页面。凭据不能写入 URL 或共享配置，也不要将所有者凭据交给模型。

上面的变量只设置在当前终端及其子进程中；管理器运行期间保持终端打开。以后重新生成凭据时，客户端也需更新。仅双击 `Start-Manager.cmd` 不会继承另一个终端临时设置的变量，首次使用按上述步骤启动。

出现 `manager_ready:true` 和 `http_gateway:true` 后，双击 `Open-Management.cmd` 打开管理窗口。选择 `example`，点击“启动项目”，再刷新并核对运行状态。注册项目不会自动启动。管理器和窗口都应使用同一账户的普通权限运行；需要管理员能力时再明确启动代理。

如果使用源码构建产物，或需要指定其他路径，可用以下命令替代包内脚本：

```powershell
$bot = 'E:\Program\ShellBot\out\x64\Release\WinShellBot.exe'
& $bot --manager --http --projects 'D:\ShellBotSettings\projects.json' --manager-data-dir 'D:\ShellBotProjects\manager\state'
# 在另一个普通终端执行以下命令，manager-data-dir 必须相同
& 'E:\Program\ShellBot\out\x64\Release\WinShellBot.exe' --manage --manager-data-dir 'D:\ShellBotProjects\manager\state'
```

使用自己的程序、配置和数据路径；启动前仍须在管理器所在终端提供配置所引用的凭据。

## 3. 连接 MCP 客户端

在管理窗口选择项目，复制本机 MCP 地址。默认示例项目为：

```text
http://127.0.0.1:8765/projects/example/mcp
```

在客户端新增支持 Streamable HTTP 的 MCP 连接，填写该地址并提供 `SHELLBOT_EXAMPLE_TOKEN` 对应的实际值。请求认证形式是 `Authorization: Bearer <项目凭据>`。客户端需要支持 ShellBot 的 JSON POST 响应及协议版本协商；具体填写位置由客户端决定，当前不支持 SSE 或标准 MCP tasks 扩展。真实客户端兼容性仍需单独验收。

项目地址和凭据必须配对。其他项目凭据或所有者凭据不能代替当前项目凭据。默认没有旧 `/mcp` 地址，只有显式配置 `gateway.default_project_id` 才提供该别名。

连接后先调用 `host_info`、`host_capabilities`，核对版本、项目、目录标识和实际能力。示例中的文件路径使用 `workspace_id: "workspace"` 和相对路径，例如 `path: "notes.txt"`。不需要模型自行猜测电脑上的绝对路径。

另一设备不能访问这里的 `127.0.0.1`。已有 HTTPS 代理需要转发到这台电脑的回环端口，再使用公共域名下相同的项目路径。可选 `gateway.public_url` 用于生成公共地址和限制请求域名；ShellBot 本身不安装隧道或提供公网 OAuth。详见 [项目网关](PROJECT_GATEWAY.md)及 [外部访问](EXTERNAL_ACCESS.md)。

只需要单实例只读文件访问、且客户端支持本机 MCP 子进程时，也可使用旧 stdio 入口：

```text
command: D:\ShellBot\WinShellBot.exe
args: --stdio --root D:\ShellBotWorkspace
```

这个入口使用只读目录 `workspace`，不通过多项目管理窗口运行；新项目配置应使用 `--manager --projects`，旧 `--config` 不接受新格式项目配置。

## 4. 文件、审批和命令权限

权限由文件范围、只读属性、审批模式、工具开关、执行身份和管理员许可共同决定。审批不会扩大目录范围，也不会将只读目录变成可写。

| 审批模式 | 当前行为 |
| --- | --- |
| `always` | 文件列表、读取、搜索、图像、写入和命令启动/输入均需批准；主机元数据查询无需逐次审批 |
| `workspace_auto` | 已授权工作目录内的文件操作自动执行；目录外已授权文件以及命令启动/输入仍需批准 |
| `never` | 已获配置许可的操作无需逐次批准；只读和身份上限仍生效 |

首次试用可保留 `always`。打开 `http://127.0.0.1:8765/owner`，输入独立所有者凭据，选择项目及普通/管理员后端，查看待审批记录。核对目标、完整参数和期限后批准或拒绝。仅打开页面或接受客户端提示不会批准。凭据只保存在页面内存中，关闭或清除后须重新输入。

工具返回 `pending`、`approval_id` 或 `approval_url` 时，完成审批后让客户端按原参数继续或重试，必要时携带对应 `approval_id`。新版客户端若收到 URL 提示，仍需所有者在页面实际批准。改变文件目标、内容或命令参数后需重新申请；过期、重启、暂停或撤销的许可不能继续使用。

当前文件工具还包括 `document_info`、`document_read`、`document_preview`。要允许写入，必须同时将相应目录设为 `read_only:false` 并在 `policy.tools` 中启用写入工具；示例未启用。覆盖或修改会核对原文摘要并保存私有备份，不能承诺崩溃原子性，详见 [文本修改](FILE_EDIT.md)。

源码 dev.18 的 `artifact_download` 用于传出完整文件，客户端先 open，经批准后沿 next_offset 读取 Base64 块并核对摘要。`artifact_upload` 用于传入新文件：open 时提供准确大小和 SHA-256，经批准后分块 write，最后 commit；不会覆盖已有文件或执行文件内容。单文件最大 64 MiB，每块最多 32 KiB。上传须显式启用工具和目录写权限；只读示例只启用下载。取消、过期或项目重启会丢弃未提交的暂存，重启不能续传。客户端需支持分块组装/发送；目前没有自动附件或匿名下载链接，具体参数见 [产物传输](ARTIFACT_TRANSFER.md)。

源码 dev.16 的 `image_view` 会完整解码 PNG/JPEG，并可加入 `max_dimension:1600` 保持比例缩小。源不超过 16 MiB 和 16,777,216 像素，返回图片不超过 2 MiB；较大的源自动缩小或转码，原文件不改动。实际尺寸与源/输出摘要随结果返回；衍生 PNG 不应用 EXIF 自动旋转，见 [图像阅读与缩放](IMAGE_VIEW.md)。冻结 dev.14 包保留旧的 2 MiB 文件头检查行为。

dev.17 文档阅读优先 PDF / DOCX / XLSX / PPTX，旧 DOC / XLS / PPT 应先转换。先用 document_info 查看单元数，再用 document_read 读取指定 unit、沿 next_offset 分页，或用 document_preview 查看 PNG。PDF 的 unit 是真实页；DOCX 只有一个正文单元，XLSX 按工作表、PPTX 按幻灯片。PDF 扫描图片不会自动识别文字；Excel 只返回已保存值，不计算公式。Office PNG 明确标注为内容预览，不保留原始页面排版、图表或图片。源最大 32 MiB，只读和批准要求与文件工具一致；详细示例见 [文档阅读](DOCUMENT_READING.md)。

要启用命令，需明确设置 `policy.execution.enabled:true`、选择身份并启用相关任务工具：

| 身份 | 配置和运行要求 |
| --- | --- |
| `restricted` | 默认身份；需显式声明 `runtime_files`，只能启动声明的程序，启动检查必须通过；限制网络、桌面调用及子进程，通用解释器或构建工具可能不能运行 |
| `current_user` | 普通账户执行；任意命令要求明确授予可写的当前账户文件范围，单靠工作目录不能构成目录隔离 |
| `administrator` | 每次操作明确选择，项目获准且共享管理员代理已启动；命令还需开启执行及工具，不因提权免除审批 |

修改配置后先保存旧配置，停止管理器，再使用新配置重启并显式启动项目。管理窗口当前只管理运行状态，不能直接编辑配置或在线重载。权限配置的完整约束见 [执行权限](EXECUTION_PERMISSIONS.md)和 [项目配置](PROJECT_CONFIGURATION.md)。

后台任务用 `task_start` 启动，保存返回的任务编号和请求键；用 `task_status` 查询状态，`task_output` 分页取输出，`task_input` 发送输入或 EOF，`task_cancel` 取消。查询已授权任务的状态、输出无需反复审批，输入另行审批。每个任务属于原项目及身份，管理员任务的后续操作也必须保留 `identity: "administrator"`。详见 [命令任务](COMMAND_TASKS.md)。

## 5. 管理员操作

默认示例关闭管理员能力。确有需要时按权限文档配置合适的项目，并明确授予管理员使用许可。受限或仅配置目录隔离的项目不能使用共享管理员代理。

普通启动时，在管理窗口点击“启动管理员”，确认后处理 Windows UAC；已获准项目复用同一个代理。以管理员身份启动管理器时，有已配置许可的项目便自动创建一次代理，复用本次管理员权限，后续 ShellBot 管理员任务和显式重启代理不再请求 UAC。普通任务保持普通身份，项目许可和原审批仍须满足。取消普通管理器的 UAC 后，管理员能力保持不可用，原操作不会降为普通权限执行。

停止代理会结束所有项目的管理员任务，普通任务继续运行；暂停或停止一个项目只结束该项目的相关任务。撤销项目管理员许可也会失效旧批准并取消该项目活动管理员任务，不能回滚已完成的文件或命令副作用。当前只接受同账户、同会话提权，跨账户提权不受支持。

运行期授权不会写回注册配置；管理器重启后按保存的配置恢复许可。无人值守登录可由首次已提升的托盘或 --admin-logon-enable 登记最高权限计划任务，之后 Windows 按该配置启动；不存储 Windows 密码，也不提供登录前桌面控制。普通 Run 项本身不提升。详见 [共享管理员代理](SHARED_ADMINISTRATOR.md)和 [启动配置](STARTUP.md)。

## 6. 日常管理和退出

| 操作 | 结果 |
| --- | --- |
| 刷新、查看诊断 | 核对项目状态和实际后端能力，复制诊断需用户明确操作 |
| 关闭管理窗口 | 管理器和任务继续运行，可重新打开连接 |
| 停止项目 | 结束该项目普通及管理员任务，其他项目继续运行 |
| 暂停项目 | 撤离该项目后端并失效许可；需明确“恢复”，普通“启动”不能解除暂停 |
| 恢复项目 | 创建新实例并保留历史，旧任务、输入和批准不会自动重放 |
| 停止管理器 | 结束其管理的项目和管理员任务 |

项目暂停状态仅存在于当前管理器运行期。重启后项目均需显式启动。正常退出可在运行管理器的终端按 Ctrl+C；也可在另一普通终端执行：

```powershell
& 'D:\ShellBot\WinShellBot.exe' --manager-stop --manager-data-dir 'D:\ShellBot\Data\Manager'
```

这里的数据目录须与实际管理器一致。退出会结束活动任务，重启只读取历史并标记中断，不自动重跑。

## 7. 数据、升级和常见问题

源码构建的 dev.15 可按 [桌面工具说明](DESKTOP_CONTROL.md)配置观察、输入和剪贴板独立权限。使用前取得短期独占控制，动作后重新观察；人工输入会暂停，默认 Ctrl+Alt+F9 紧急停止，只能由本机所有者明确恢复。暂停恢复与项目暂停是不同入口；桌面权限覆盖当前会话内容，目录只读不限制它。完整只读示例见 [desktop.example.json](../config/desktop.example.json)。

实际配置、凭据、管理器和项目 Data 是自己的运行资料。升级前停止相关进程并备份；保留旧程序包及修改前配置。当前没有自动迁移、历史淘汰或升级回滚功能，不要用全新包覆盖或删除原 Data。

源码 dev.19 可准备私有启动文件，在“登录后托盘”与“开机服务”中选择，也可用独立端口和 Data 同时运行。托盘单击打开管理，关闭窗口继续后台运行，退出明确停止本实例。服务使用独立虚拟账户，工作目录须授予该账户对应权限；桌面和管理员操作仍使用登录会话的普通实例。凭据与项目配置保存为加密快照，更新后须明确切换，旧批准和任务不自动恢复。完整命令和登录登记/实际服务当前待验收项见 [常驻说明](STARTUP.md)。

私有历史有大小、记录和实例数预算，达到上限时会拒绝新操作或启动；先停机审阅、归档，再准备新的数据位置。审批审计与文件备份也应保留，详情见 [审计](AUDIT.md)及 [历史与恢复](REMOTE_APPROVALS.md)。

| 现象 | 处理 |
| --- | --- |
| 管理器启动提示凭据缺失或重复 | 在管理器所在终端设置配置引用的环境变量；所有启用项目及所有者值须独立 |
| 管理窗口连接失败 | 核对管理器已运行、账户与普通权限一致、两处 manager-data-dir 相同，再刷新 |
| 项目地址返回不可用 | 在本机窗口核对是否已启动、暂停或退出；地址不会自动启动项目 |
| 请求认证失败 | 核对项目地址和对应 bearer；所有者凭据只用于审批入口 |
| 文件或命令被拒绝 | 查看 host_capabilities 和诊断，检查范围、只读、工具、身份、审批及后端是否可用 |
| 受限任务后端不可用 | 保留旁置 SandboxProbe，并检查声明的运行文件和启动验证结果 |
| 管理员不可用 | 检查项目许可、实际代理状态和普通令牌诊断；普通启动需明确允许 UAC，无人值守登录须预先登记最高权限任务 |
| PDF 后端不可用或摘要不符 | 核对主程序旁的 pdfium.dll 与当前架构、固定版本一致；重新构建或从同一可信构建恢复依赖 |
| Office 格式或内容被拒绝 | 将旧格式、宏格式或加密文件转换成无宏、未加密的 DOCX / XLSX / PPTX；损坏或超过预算的包不能读取 |
| Office 预览与原文件页面不同 | 当前为结构化内容预览；原始排版渲染尚未实现 |
| 改配置后行为未变化 | 保存配置后停止管理器，切换配置并明确重启；窗口不在线重载 |
| 端口 8765 被占用 | 停止旧实例或在 gateway.port 中设置其他端口，同时更新客户端和已有代理转发 |

开发机中间编译文件、Python 字节码和 IDE 索引可重建；候选包、回退基线、验收报告、实际配置和 Data 应单独保留。测试源码及脚本已退出 Git 跟踪，本地副本保留；源码默认构建不依赖它们。
