# ShellBot 使用说明

适用版本：**1.0.0**，Windows x64。

完整解压正式便携包，双击 **ShellBot.exe**。首次直接显示项目管理窗口，空列表可以立即新建项目。使用普通 Windows 账户权限即可；配置、启动、端口、令牌和退出均在界面完成。

### 管理界面

使用原生 Windows 菜单与系统控件。顶部右侧管理连接、客户端授权和数据位置。左侧是项目列表，新建按钮位于列表标题旁，刷新按钮位于列表下方。右侧显示所选项目名称与状态，项目设置、启停/暂停/恢复及详情都在同一区域；右侧下方复制地址、项目令牌或查看诊断。管理员代理和审批令牌位于“工具”菜单，完整地址/令牌命令也可从“连接”菜单选择。数据路径移到底部。

“视图 → 经典布局”可随时切回经典排版，“视图 → 项目优先布局”返回新版。切换保留当前项目、详情选区和阅读位置，不修改项目权限，也不重启项目。排版选择只在本次窗口中保留，下次打开默认使用项目优先布局。本版变化见 [1.0.0 发布说明](RELEASE_NOTES_1.0.0.md)。

`F5` 刷新，`Ctrl+N` 新建项目，`Ctrl+E` 打开项目设置，`Ctrl+L` 打开客户端授权。菜单支持 Windows 的 Alt 快捷导航。Tab 顺序跟随当前布局的操作分组；项目列保留可读宽度，必要时横向滚动。

项目、连接和数据位置表单可按 Enter 执行默认保存操作，按 Escape 取消。客户端授权窗口默认 Enter 关闭窗口，不会自动同意连接；批准仍需明确选择“允许此连接”。

自动刷新保留文本选区、阅读位置和诊断。短暂连接失败保留最后一次内容，并在底部提示状态暂未更新；此时项目操作暂停可用，恢复连接后自动更新。切换项目后，稍晚返回的旧项目诊断不会覆盖当前详情。手动刷新会从诊断返回项目摘要。

“文件 → 退出并停止全部项目”和托盘退出执行相同的关闭流程。窗口右上角关闭仍收进托盘。

### 新建项目

1. 点击“新建项目…”。
2. 填写项目名称，支持中文。地址标识可在创建前修改，只允许 1～63 个英文字母、数字、下划线或连字符；创建后保持固定。
3. 默认项目目录位于程序旁的 `Data\Projects`。可以改为独立、可写的非 C 盘本地空目录，例如 `D:\开发\ShellBot\测试项目`。
4. 默认工作目录为该目录下的 `Workspace` 子目录。存储根目录保存内部配置，`State` 保存运行数据；工作目录用于 MCP 操作文件。
5. 按需要设置工作目录只读和审批方式。“权限、目录与工具…”可设置更多目录、具体工具、命令身份及桌面权限。
6. 点击“创建项目”。项目立即出现在主界面列表；默认勾选“随管理界面启动此项目”，创建后即启动。取消该选项时，可在列表中手动启动。

项目凭据由程序生成，并与项目配置一起通过当前 Windows 账户加密保存。右侧“项目令牌”或“连接 → 复制项目令牌”用于客户端认证；不需要手动设置环境变量。

### 端口与客户端连接

在主界面点击“连接设置…”，填写本机监听端口，即已有隧道的本机目标端口。只监听 `127.0.0.1`。公共地址为可选项，可填已有 HTTPS 域名，用于生成公共链接。应用连接设置会提示停止活动任务并重新建立网关；项目按“随管理界面启动”设置重新启动，旧任务不会重放。

在“连接设置”填入 HTTPS 公网域名地址，例如 `https://你的域名`，不要添加 `/projects/...` 路径。OAuth 会自动启用，域名和隧道继续使用你已有的配置。当前数据目录中保存的 HTTPS 公共地址和项目会直接复用。

1. 选中运行中的项目，点击右侧“公网地址”或“连接 → 复制公网地址”。例如标识为 `ShellBotTest` 时，地址为 `https://你的域名/projects/ShellBotTest/mcp`。
2. 在 ChatGPT“添加自定义 MCP 服务器／创建为插件”中粘贴地址，认证选择 **OAuth**。使用自动／动态客户端注册（DCR）；无需手动填写客户端 ID、客户端密钥或项目 token。若客户端询问 scope，可使用 `mcp offline_access`。
3. 客户端打开授权页，显示申请编号，并等待你在运行 ShellBot 的电脑确认。
4. 打开 ShellBot 管理界面的 **“客户端授权…”**，选中“待确认”申请，核对浏览器中的编号、项目和完整回调地址。默认勾选 **“长期授权，直到手动撤销”**，点击“允许此连接”。客户端名称由对方提供，不能单凭名称判断来源。取消勾选可使用 30 天限时授权。
5. 浏览器返回客户端，完成安装。之后请求携带独立的访问凭据，不需要将 token 粘贴到对话或 URL 中。

访问凭据每次有效 15 分钟，由客户端自动续期。长期授权没有固定到期日，首次人工确认后无需定期回到运行 ShellBot 的电脑；重启、迁移目录和修改项目权限后继续有效。它允许客户端使用项目当前权限，包含之后新增的权限，每次工具调用仍受当前目录、工具、任务身份和审批规则检查。限时授权最长 30 天，实际权限变化后仍需重新授权。

正常续期不会立即作废尚未到期的访问凭据，原到期时间保持不变。续期凭据每次轮换；重复使用已消费的旧续期凭据会撤销整条连接。退出管理器会停止所有项目；重新打开后可继续使用已保存的授权。尚未完成的授权申请和授权码在重启后失效，需要重新连接。

“客户端授权…”可查看授权方式、连接状态和撤销原因，也可拒绝申请、撤销项目连接或移除登记客户端。登记不代表已经授权。撤销立即禁止后续请求，重启后仍生效；它不撤销已执行的操作或停止已开始的任务，需要结束任务时请停止项目。移除客户端会终止其所有连接。删除项目后用相同标识新建项目，不能继承原长期授权；更换项目凭据、更换公网域名、清除凭据或更换 Windows 账户后需要重新连接。

窗口底部显示本次运行中最近一次认证失败原因，成功连接不会清除此历史提示。旧续期凭据重用导致的撤销原因会加密保存。该诊断不包含访问令牌、续期凭据或回调参数。长期授权是 ShellBot 的服务器端授权策略；若客户端删除连接、丢失凭据或要求再次登录，仍需从客户端重新连接，ShellBot 不能代替客户端保存凭据。

升级前从托盘退出旧版，并在非 C 盘备份原数据目录。1.0.0 可读取旧版 v1/v2 OAuth 存储，后续保存为 v3。旧连接保留原限时规则，不会自动变成长期授权。需要长期连接时，升级后从客户端重新连接一次，并在本机勾选长期授权。旧的失效记录可手动撤销；无需清空所有数据。回退旧版时须同时恢复更新前的数据备份，旧版不能读取 v3。项目文件与凭据请保留。

OAuth 仅解决客户端连接认证，不扩大项目的文件范围、工具、任务身份或管理员权限；原有逐次操作审批继续生效。只有本机所有者管理界面和受保护的本机管理通道能批准 OAuth 连接，远程所有者审批页面不能替代此步骤。

兼容客户端仍可使用 `Authorization: Bearer 项目令牌` 请求头和“复制项目令牌”。URL 查询参数不接受 token；ChatGPT 插件请选择 OAuth，避免选择“无需身份验证”。参见 [OpenAI 自定义 MCP 说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)及 [认证说明](https://developers.openai.com/plugins/build/auth)。

需要审批时，使用工具返回的所有者审批地址，或在浏览器打开 `http://127.0.0.1:端口/owner`。“复制审批令牌”取得独立所有者凭据；它与 MCP 项目令牌用途不同。隧道、域名映射和 MCP 客户端安装沿用已有环境。

### 修改项目及存储目录

选中项目，点击“项目设置…”。可修改中文名称、存储位置、工作目录、审批、自动启动及高级权限。地址标识和令牌保持稳定。

实际权限或目录变化会停止该项目并按原运行状态重新启动；未改动保存或只修改显示名称、自动启动选项不重启工作进程。其他项目继续运行。存储目录变化时，选择新的空目录，程序复制项目配置和数据、逐文件校验 SHA-256，成功后切换。存储目录内的工作目录和运行资源路径随迁移调整，外部目录仍保留原路径。原目录保留用于恢复，旧执行许可不会恢复，任务不会重放。

自动刷新只更新发生变化的项目内容；不会周期性禁用再启用按钮。阅读位置、文本选区和诊断视图继续保留。

保存失败时保留原配置及原目录。因取消或失败而留下的部分目标文件会保留供检查；请按提示选择其他空目录或处理已复制的目标。项目目录之间、项目数据与授权工作目录之间的冲突会被拒绝。

### 关闭和退出

点击窗口关闭按钮或 Alt+F4，窗口收进系统托盘，项目和后台任务继续运行。单击托盘图标重新显示管理窗口；也可以再次双击 ShellBot.exe，激活同一实例。

在托盘图标上右键，选择 **“退出 ShellBot（停止全部项目）”**。退出会停止本实例所有项目、后台任务和 HTTP 网关。若目录复制尚在进行，退出会取消迁移并保留原索引与全部源文件；已完成的配置提交保留完整新版本。托盘暂不可用时窗口保持可见，并等待托盘恢复。

管理程序是唯一的托盘图标。项目的桌面控制入口集中在该图标的“桌面控制（本会话）”子菜单，显示当前暂停状态、全会话暂停/恢复以及启用桌面控制的项目入口。恢复需确认，并等待 500 毫秒；期间新的本机输入会取消恢复。它与“暂停项目”用途不同，不会停止文件工具或后台命令。

项目设置中的控制租约上限（1～120 秒）只限制一次桌面工具独占使用的有效期，默认 30 秒。客户端可在到期前显式续租；到期不会停止项目、后台任务或撤销 OAuth 连接。详见 [桌面工具与租约](DESKTOP_CONTROL.md)。

重新打开后读取已保存项目，按每个项目的自动启动选项启动工作进程。历史任务、审批、审计和备份保留；旧任务不会重新执行。

管理器后台自动刷新会保留右侧详情的选区和阅读位置。查看诊断时，自动刷新继续更新左侧状态并保留诊断内容；点击“刷新”返回项目详情，切换到其他项目时从新项目的开头显示。

### 便携数据位置与迁移

默认应用数据全部放在 **ShellBot.exe 所在目录的 `Data` 文件夹**，不再读取或创建 LocalAppData、用户“文档”目录中的 ShellBot 数据。`Data\Desktop` 保存项目索引和加密凭据，`Data\Desktop\Manager` 保存管理器及 OAuth 状态；默认项目在 `Data\Projects`，各自保存配置、`State` 和 `Workspace`。

主界面的 **“数据位置…”** 可以修改应用数据目录。选择独立的非 C 盘空目录后，程序停止全部项目，先复制并逐文件核对 SHA-256，再更新内部项目路径并保存新位置。完成界面会列出原位置和新位置；点击“完成并退出”，重新打开 ShellBot 后使用新位置。确认新位置正常后，可手动删除旧目录。复制、校验或位置设置保存失败时保留原配置和目录；目标中的已复制文件也保留供检查。

位置设置保存在程序旁的 `ShellBot.storage.json`，默认位置不需要该文件。修改位置后，这个小文件必须与程序一起保留。程序目录在 C 盘或不可写时，会明确询问非 C 盘数据位置；无法保存位置设置时会提示下次启动需要重新选择，不会写入 C 盘或悄悄改用系统目录。建议将整个程序解压到可写的非 C 盘目录。

使用默认 `Data` 时，退出后可以移动整个程序文件夹。重新打开会更新内部路径。另行指定的应用数据目录保持独立；另行指定的项目存储目录在“项目设置…”中迁移。应用数据和项目存储路径均拒绝 C 盘，以及实际指向 C 盘的目录别名；不限制按项目权限明确授权的 C 盘文件操作。

日志、审计、任务状态、图片与文档产物均使用所选数据目录。ShellBot 和工作进程的临时、缓存及应用配置环境目录放在数据目录的 `Runtime` 子目录；受限进程只获得自己的临时目录权限。受限命令也不在 C 盘创建沙盒配置目录，并继续验证原有隔离边界。

OAuth 状态仍由当前 Windows 账户加密。目录移动不会解除账户绑定；不能把加密凭据当作可跨账户使用的普通便携文件。路径变化会增加相关项目的策略版本，旧执行许可和限时 OAuth 连接需要重新授权；长期 OAuth 连接与客户端登记保留。每次操作按更新后的目录权限检查，已有任务不会重放。

### AdGuard 与本地代理

开发机对照确认 AdGuard 的 localhost 过滤可能影响 TCP 半关闭。程序已加固错误响应和连接关闭流程，仍须配合过滤环境设置。本轮保留 AdGuard 服务和 localhost 过滤，仅使用已配置的固定程序路径排除；验证环境见包内 `validation/acceptance.json`。

关闭 localhost 过滤可能影响浏览器经本机代理的网页过滤。需要本地代理过滤时，可保留 localhost 过滤，仅对 ShellBot 相关程序添加排除，并分别复验 MCP 连接与浏览器过滤。本轮四项固定路径排除后，独立探针及严格 EOF/响应回归通过；浏览器、代理和系统 Python 未加入本轮排除，其实际网页过滤效果没有独立测试。正常使用可把程序放在固定的非 C 盘目录，在 AdGuard 高级设置的“过滤时按完整路径排除应用”中追加该目录下 `WinShellBot.exe` 的完整路径；保留已有项，多项以分号分隔。升级时更新同一路径下的程序，避免白名单因目录变化而失效。独立探针和专用客户端属于开发回归工具，不随正式程序分发。该选项见 [AdGuard 高级设置说明](https://adguard.com/kb/zh-CN/adguard-for-windows/settings/app-settings/advanced-settings/)。

当前版本的本机功能、严格 EOF、便携迁移、OAuth 和解压验证以包内 validation 收据为准。历史失败原样保留，不能将单次通过或跳过 EOF 的测试当作稳定性结论。真实 MCP 客户端、新版本实际管理员和独立机器仍由各自专项验收。
### 升级与常见问题

1. 从托盘退出旧版，确认项目和任务已经停止。
2. 在非 C 盘备份原 Data，以及存在时的 `ShellBot.storage.json`。
3. 将新包完整解压到原固定程序目录，替换程序和随附依赖，保留数据与位置设置。
4. 双击 ShellBot.exe，检查项目、数据位置和客户端连接。dev.26–dev.28 的 OAuth v3 格式保持兼容。

| 现象 | 处理 |
| --- | --- |
| 无法监听端口 | 在“连接设置…”选用空闲端口，并同步已有隧道目标；不要同时启动占用同一端口的旧版 |
| 启动提示缺少组件 | 重新完整解压同一发布包，保留主程序、SandboxProbe 和 pdfium.dll |
| 客户端再次要求授权 | 查看“客户端授权…”中的状态和原因；核对域名、账户及凭据是否变化，按需重新连接 |
| 文件或命令被拒绝 | 查看诊断，检查目录范围、只读、工具、审批与实际执行身份 |
| 移到另一账户后无法读取凭据 | 凭据绑定原 Windows 账户；在新账户重新配置项目和连接 |
| 文档预览与原排版不同 | Office 为结构化内容预览；PDF 才按真实页面渲染 |
