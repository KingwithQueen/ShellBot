# 文本覆盖和局部修改

版本：Windows 1.0.4。创建、覆盖及修改的原文件和结果最高各 8 MiB。

修改要求授权目录可写，并遵循项目配置的审批模式；旧 root 配置入口仍要求本机所有者审批。fs_write 默认行为仍是创建新文件；只有明确 overwrite:true 并提供原始字节的 expected_sha256 才能修改既有文件。fs_patch 是字面量文本替换，默认只允许恰好一次匹配。读取完整文件时 fs_read 返回 sha256，包含文件原始 BOM；分页结果不把前缀摘要冒充整文件摘要。较大文件可提高 max_bytes 或通过产物下载计算完整摘要。

## 覆盖

```json
{
  "workspace_id": "workspace",
  "path": "example.txt",
  "text": "完整的新文本\n",
  "overwrite": true,
  "expected_sha256": "从完整 fs_read 得到的 64 位十六进制 SHA-256"
}
```

先得到 pending 和 approval_id。本机 --inspect 可同时查看 original_text、最终 text、两份摘要和文件身份；检查后 --approve。以同样的工具参数加 approval_id 重试才执行。哈希允许大小写，但必须是 64 个十六进制字符。没有 overwrite:true 时仍不覆盖已有文件，也不接受 expected_sha256。

## 局部替换

```json
{
  "workspace_id": "workspace",
  "path": "example.txt",
  "search": "需要替换的文字",
  "replacement": "替换后的文字",
  "expected_sha256": "原始文件的 SHA-256",
  "expected_matches": 1
}
```

search 必须非空，replacement 可以为空，expected_matches 范围 1～1000。匹配区分大小写，按 UTF-8 字节中的完整文本执行非重叠字面量替换；支持中文、emoji 和跨行文本，不解释正则。实际次数不符时拒绝，不创建审批或备份。未匹配部分保持原样，包括 BOM 和换行；覆盖则按调用者提供的新文本完整写入。无实际变化的修改会拒绝。

审批绑定调用身份、目录、路径、工具、原始摘要、输入文本或替换参数及匹配次数。执行时通过已经核验的父目录打开原文件，核对父目录身份、文件身份和内容摘要。原文件被编辑、移动或用同样内容的新文件替换，都不能沿用旧审批。完成和失败的相同 approval_id 重试返回已记录的结果，不再次写入；这是先前执行结果，不是文件此刻状态的重新检查。拒绝、撤销、过期和重启失效仍适用。

## 保存与恢复

本版采用原文件独占句柄和私有备份保存，返回 atomic_save:false；不承诺崩溃原子性。它保留原文件身份与 ACL，不通过文件名替换原对象。原文件已被其他读写者占用时拒绝。

执行前把完整原字节保存并刷新到该实例 Data 目录的 backup-<backup_id>.bin，ACL 限制为当前用户和 SYSTEM；审计记录 backup_saved、原始摘要和 backup_id 后才修改原文件。备份或该审计事件失败时原文不动。常规写入失败会尝试在同一句柄恢复原字节，结果明确报告恢复是否成功。进程突然退出、断电或恢复失败时，需要所有者从报告或审计定位私有备份，核对原始摘要后手动恢复。程序不自动回放旧审批或恢复文件。

每个实例最多申请 64 个备份槽，每份最多 8 MiB，最多 512 MiB。备份保留供所有者恢复，不自动按文件名删除；重启创建新的实例预算，长期保留的磁盘空间由所有者管理。备份创建失败也可能占用槽，并留下空或未完成的私有文件；只有返回的 backup_id 或已记录的 backup_saved 对应的已刷新备份才可作为完整原文使用。审计不记录原文或修改后的正文，备份是独立的私有二进制文件。

原文和结果均限于 8 MiB 以内的 UTF-8 文本。UTF-16、二进制、多硬链接、符号链接、重解析文件、只读文件、目录和越界路径拒绝；本版不做隐式编码转换。开发机 E: 为 ReFS，硬链接夹具无法创建，该项在验证报告中明确列为 skipped；原生实现检查链接数，NTFS 多硬链接拒绝尚需独立验证。普通 I/O 失败后的恢复分支和突然中断后的手动恢复尚无故障注入验收，不扩大为已验证的崩溃恢复能力。
