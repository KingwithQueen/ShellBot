# dev.28 管理界面排版预览

日期：2026-10-21，北京时间。用户已认可 dev.27，在其基础上尝试更美观、易用的排版。业务层继续沿用 C17 / Win32 实现。

## 设计

默认采用“项目优先”布局，让操作尽量靠近它影响的内容：

- 顶部只放连接设置、客户端授权和数据位置三个全局入口。
- 左侧项目列表的标题旁放新建，下方放刷新；项目总数直接显示在标题中。
- 右侧用项目名称与状态作为标题，设置和启停操作放在该项目区域中。
- 详情使用系统白底，减少大段灰底文字的视觉负担。地址、令牌和诊断操作集中在详情下方。
- 管理员代理和审批令牌仍可从“工具”菜单使用；全局功能没有移除。
- 状态提示和数据路径放到底部，项目内容获得更集中的展示空间。

“视图 → 经典布局”保留 dev.27 的原排版；“项目优先布局”回到新版。两种布局均使用原生控件和系统颜色，支持键盘操作。切换只改变本次窗口的呈现方式，不保存项目配置，不改变权限，不重启工作进程。下次启动默认使用项目优先布局。

## 相关实现与验证

界面改动集中在 `WinShellBot/platform/manager_ui.c`：布局、系统颜色、项目标题、视图菜单和 Tab 顺序。详情文本、后台请求、审批与授权处理继续沿用 dev.27；版本升级为 `0.1.0-dev.28`，本机版本断言同步更新。

本轮报告独立保存在 `build/layout-validation`。构建仍为 x64 Debug / Release，沿用现有警告视为错误配置。相关检查包括：

- 两配置下，两种布局分别在 1000×650、1160×800、1400×900 的逻辑窗口尺寸中核对控件可见性、边界和按钮重叠。
- 视图切换保留所选项目、文本选区、滚动位置及诊断；核对切换前后工作进程实例和策略版本一致。
- 核对少用操作仍在菜单、原生 Tab 顺序与分组一致，反复切换后的 GDI 使用稳定。
- 重跑自动刷新/阅读位置、延迟诊断和失败快照保护；Release 另跑项目管理、弹窗键盘、公开启动入口、完整退出和授权窗口检查。

这里的尺寸和 DPI 消息检查不替代物理多屏 DPI 验收。真实客户端、实际 UAC、独立 Windows 系统及长期运行仍按原专项范围另验。本轮没有改动 HTTP/OAuth 协议、项目权限、隧道或系统过滤设置；没有把旧版本完整压力结果当作 dev.28 的压力证明。

原始测试发现与处理：初始化等待条件和视图菜单取样时序已修正；窗口足够高、全部文本可见时不能断言其仍有非零滚动位置，因此滚动检查在小窗口中进行；原生绘制缓存释放导致 GDI 数量下降，资源检查核对稳定后不增长。所有原始失败 JSON 保留。实际代码补充了视图切换时的阅读位置恢复，菜单选中标记在布局完成后更新。

现用 dev.27 实例正在使用默认 8765 端口，首次桌面回归因此无法建立独立管理器；原失败记录保留。后续测试预置自己的空项目索引并选择独立回环端口，现用实例和真实项目保持运行，不停止进程或修改其连接设置。
