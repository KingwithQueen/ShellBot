## 实现

新增 Windows startup.h / startup.c / service.c、app/launcher.c、Launcher.vcxproj 及 service.example.json，默认产品构建同时生成 ShellBot-Launcher.exe（GUI subsystem），C17 / 静态运行库，无新外部运行时。Crypt32 来自 Windows。原主程序命令、项目格式和 32 个 MCP 工具保留；启动与 SCM 管理只通过本机命令/托盘，不开放给 MCP。

--startup-prepare 捕获完整项目配置和启用项目/所有者凭据，用 DPAPI 保存单个 create-only 私有文件；不登记/运行/改源配置。托盘用 user 范围、服务用 machine 范围并依赖严格私有 ACL。解密设置 32 KiB、文件 64 KiB，必须在授权目录和运行 Data 外。--startup-inspect 可审阅准确的配置快照及项目选择，不返回凭据值。更新源配置或凭据后须明确创建新快照并切换。仅 --start-project 选定的项目启动，不复用旧批准/任务/传输；失败项目可检查，不自动重跑。

托盘用 --resident，在本进程管理器线程运行，新相邻 GUI 启动器以 CREATE_NO_WINDOW 启动主程序。只隐藏自己的控制台/窗口，不操作调用者终端。图标登记成功后隐藏管理窗口；单击打开、关闭隐藏、退出/manager-stop 清理本人进程和任务。定时器与 TaskbarCreated 恢复图标，图标失败显示窗口。真实注册回执以窗口属性供本地验收观察；不把它当作物理用户点击。

登录自启使用每个规范路径摘要对应的独立 HKCU Run 值，完整引号命令，仅修改准确匹配的自己的值，拒绝覆盖/删除不同命令；关闭/状态查询支持启动文件已删除的原路径。移动前先关闭旧登记。实际登记写入在同一产品的专用子进程内，句柄白名单、暂停创建/Job 归属、20 秒等待；超时明确返回状态未确认并关闭辅助进程，不重试。托盘设置在后台处理，主机继续响应，用户可退出；源码保留只输出固定阶段名的 SHELLBOT_STARTUP_TRACE 诊断。

服务固定 ShellBotService，虚拟账户 NT SERVICE\ShellBotService，无 Windows 密码、无 LocalSystem 工具身份。SCM 入口核对实际 SID、Session 0、未提升/非受限令牌。服务项目仅允许本地 configured 范围、独立 owner_token_env、无旧兼容/桌面/管理员/账户任意命令；受限任务仍需实际后端核验。管理员安装终端由所有者明确打开，产品不自动弹 UAC。绑定准确主程序、启动文件、账户和服务类型；同名其他服务拒绝修改或删除。安装为自动（延迟），不立即启动；只授予启动文件读取，创建新私有 Data 或复用已有私有服务 Data，不转换无关 Data，不改变工作目录 ACL。工作目录/程序权限由所有者单独授予服务账户。

控制器报告 START_PENDING / RUNNING / STOP_PENDING / STOPPED；停止/系统关闭发出停止信号并清理，异常清理等待后结束本服务，由已有 Job 收尾。没有配置自动失败重启。start 请求不冒充已运行；uninstall 要求 stopped，并保留 Data/启动文件/历史，不删除目录。服务所有者审批使用该服务的 /owner 页面；普通账户本机管道不跨 SID 接管。--startup-console 可用同一服务策略作前台诊断，实际身份仍为诊断调用者，不代替 SCM/虚拟账户/开机验收。

两模式同时运行须独立端口及 Data；同 Data 第二实例拒绝且不接管第一实例。原 --manager 不默认启动项目，原 --manage 关闭不停止管理器。参数、账户区别与详细安装步骤见 [STARTUP.md](STARTUP.md)。
